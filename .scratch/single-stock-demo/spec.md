## 2. 目标

用一份冻结、真实、可重复验证的单股票数据快照，验证以下完整业务链路：

```text
取数与解析
  -> 上下文治理
  -> 技术标准化与会计规整
  -> 信源治理与确定性核验
  -> 分析与固定框架评分
  -> 反方质询
  -> 内部结构化报告
```

主要成功标准不是预测准确率，而是报告准确、全面、可核验：每个数字带来源与时点，重要判断能回溯到治理证据，冲突、反证、UNKNOWN/TBD 和质询修订均被保留。

## 3. 研究问题、分析框架与交付要求

这三层必须在 Skill 指令、数据契约和报告中保持分离，不能以“流程已完成”代替“研究问题已得到证据约束的回答”。

### 3.1 主研究问题

> 截至 `{as_of}`，中芯国际的经常性经营盈利能力发生了哪些可验证的变化，现有证据在多大程度上支持其已进入可持续改善阶段？

问题保持开放，允许得到以下任一结果：支持、部分支持、反驳或证据不足。不得预设产能利用率、结构或资本开支必然共同支持改善。

### 3.2 分析框架

1. 结果核验：统一口径后，盈利能力发生了什么变化。
2. 驱动路径：产能利用率、制程/应用结构和资本开支转化分别通过什么机制影响结果。
3. 替代解释：行业周期、政府补助和其他非核心因素能解释多少，是否存在重复归因。
4. 证据状态：哪些已核验证据支持或反驳命题，哪些缺口会使结论降级或被推翻。

### 3.3 交付要求

交付的是被治理和质询过的结构化分析报告与可追溯中间产物，不是推荐或预测产品。报告必须：

- 对每个数字给出来源、公开时点、报告期间/时点和定位；
- 区分报告事实、派生指标、管理层观点、第三方观点和分析归纳；
- 展示口径桥接、公式、冲突、隔离项、反证、限制和修订；
- 对无法确认的内容输出 UNKNOWN/TBD，并注明确认人和所需证据；
- 不输出交易指令、仓位建议、目标价、估值锚、投资吸引力判断或系统预测。

## 6. 编排要求

### FR-001 固定顺序

编排器必须按以下顺序工作：

```text
acquire-research-materials
  -> govern-research-context
  -> normalize-research-facts
  -> govern-and-validate-research-evidence
  -> analyze-and-score-research-findings
  -> challenge-research-findings
  -> generate-research-report
```

阶段 Skill 不得自行调用其他阶段 Skill。质询要求修订时，由编排器将明确的目标 `finding_id`/`evidence_id` 和问题返回分析阶段或所需上游阶段。

### FR-002 简单编排

编排器只负责固定顺序、输入存在性、阶段结果、停止/降级条件和最多两轮质询。不得实现通用 DAG、队列、调度器、状态机平台、数据库、动态模型路由或插件系统。

### FR-003 失败与降级

- 已确认发布时间晚于 `as_of` 的内容在采集阶段直接排除。发布时间窗口跨越 `as_of`，或缺少可追溯采集来源、展示发布主体、发布时间/窗口、材料定位中任一项的高相关候选，放入 Snapshot 外的 Candidate Holding Area，待补齐证据并由用户确认后再进入新的快照。
- 已满足采集最低门槛但当前无法可靠解析的材料仍可冻结；它不得产生 chunk、fact 或 evidence，并登记采集缺口。单位/期间无法解释、确定性公式失败或下游资格不合格的记录由相应治理阶段隔离。
- 某项数据隔离不等于整个流程无输出；后续发现按可用证据降级，必要时为 UNKNOWN。
- 即使 `governance_status=FAIL`，也要生成内部诊断报告，明确失败、隔离范围和影响。
- 失败或缺数不得被默认值、模型常识或运行时 Web 补数掩盖。

## 7. 取数与冻结快照

### FR-010 两种使用模式

- `SNAPSHOT_BUILD`：允许通过公开 Web 检索、文档下载、结构化数据获取或用户人工提供来建立新的自包含快照。任何材料或元数据修订都产生新身份，不覆盖旧快照。
- `DEMO_RUN`：只读取指定冻结快照，校验身份、内容哈希、`as_of` 资格和采集最低元数据；禁止实时刷新、临时联网补数，也不得把 `restriction_status=USABLE` 或已完成证据治理作为运行前提。

快照内容必须真实，不得生成、猜测或伪造来源、API、字段、数值和文档。

Snapshot v1 `smic-4c110e93f810aa8e` 和 Snapshot v2 `smic-95dcd12eba2fe17c` 均保持原身份、状态和文件不变。当前 Snapshot v3 `smic-a283e95e2c9e8068` 完整列出并携带自身运行所需的 20 份材料；其 `parent_snapshot_id` 只表达 v2 血缘，运行时不得依赖 v1/v2。所有进入 v3 的材料统一为 `ACQUIRED_UNASSESSED`，下游治理结论不得回写快照状态。

### FR-011 材料类型

取数阶段可登记公告、财报、业绩说明/电话会文字稿、公司正式材料、政策、行业数据、具名机构研究与一般 Web 页面。解析 PDF、HTML、表格或文本后，只形成带定位的研究材料，不直接形成证据。

Demo 支持解析带有可靠文本层的 PDF，包括正文、表格、页码、章节、脚注及其定位。允许将页面渲染为图片，用于核对抽取结果、表格结构和版式；正式溯源必须指向原始 PDF、页码和内容哈希，`tmp/pdfs` 中的抽取文本或页面图片只能作为辅助产物。

Demo 不做音频转写、图片或图表数值理解，也不对扫描件或纯图片 PDF 执行 OCR。只有已有文字稿可以作为音频类材料的候选输入。满足采集最低门槛但当前无法提取的材料仍以原始文件冻结，标记 `parse_status=UNSUPPORTED` 或 `PARTIAL` 并登记 Acquisition Gap；在取得可处理版本前，不产生 chunk、fact、evidence，也不在采集阶段提前写事实 UNKNOWN。

### FR-012 准入元数据

每份进入快照的材料必须至少保留：

- `material_id`、`source_id`、标题和展示发布主体（Displayed Publisher）；
- 原始发布时间文本、精度、发布时间窗口及判定依据；
- 可定位整份材料的 Canonical Material Locator，以及可选 Alternate Material Locators；
- 媒体类型、内容哈希、冻结路径、`as_of` 资格、`ACQUIRED_UNASSESSED` 状态、解析状态；
- 至少一个 `acquisition_target_id`，表示采集原因而非覆盖程度。

页码、章节、表格、段落或数据行属于 Content Locator，由解析/上下文治理阶段生成，不是采集准入门槛。条款 URL、已知限制和 `usage_basis` 采用 best-effort 记录，不是采集阻塞条件。

如果同一内容哈希来自多个定位，只保留一个材料记录和一份冻结文件；按“发行人 -> 监管/交易所 -> 具名机构 -> 其他稳定来源”的机械顺序选择 Canonical Material Locator，其他入口记为 Alternate Material Locators。这不是信源等级或真实性判断。内容哈希不同的版本均可保留，交由后续治理。

高相关候选若无法记录采集来源、展示发布主体、发布时间/窗口或 Material Locator，不获得 `material_id`，不得进入任何 Snapshot、RAG、facts、analysis 或 report；应进入 Candidate Holding Area，直到缺失证据补齐并由用户确认后，才可进入一个新的快照。

### FR-013 来源使用边界

当前假设为个人、非商业、本地使用：

- “可获取”包括公开材料，以及用户通过自己的账号、权限或其他合法渠道手动提供的材料；
- 注册、登录、验证码和会话由用户在 Demo 外手动处理；项目不得保存账号、密码、Cookie、Token 或其他会话信息，不自动登录，也不绕过访问控制；
- 条款 URL、已知限制与 `usage_basis` 尽力记录，缺失时也不阻塞个人本地采集；项目不建设法务审批流，也不以 `restriction_status=USABLE` 作为准入条件；
- 已取得材料的真实性、原始性、完整性、可信度、信源等级、同源关系、冲突、隔离与分析资格全部留给后续证据治理；
- 已确认发布时间晚于 `as_of` 是唯一直接排除内容本身的业务条件。其余当前可获取且与采集目标相关的材料尽可能冻结；
- 原始材料仅保存在个人本地环境，不对外重新分发；
- 一旦用途变为团队共享、公开展示、客户交付、商业产品或模型训练，来源许可重新成为 P0。

### FR-014 采集目标

核心观察期为 FY2023 至 2026 Q1。更早材料只用于期初基线、交易链、子公司/合并范围、会计政策/重述或必要的行业周期基线。当前 v3 沿用以下固定采集目标：

1. 公司与证券主数据；
2. 2023、2024、2025 三份完整年度材料集；每年至少包含完整合并 IFRS 报告，并在可获取时另收 A 股 CAS 报告或披露，不能用 2025 年报的三年/五年摘要代替 2023、2024 完整年报；
3. 2025 Q2、Q3、Q4 和 2026 Q1 四套完整季度材料集；每期目标包括发行人业绩公告/结果、财务报表或详细附录、演示材料、已有文字稿/Q&A/纪要和相关交易所披露，某一类型不可获得时登记采集缺口但不阻塞快照；
4. 产能、利用率、出货、ASP、制程/应用结构和资本开支；
5. 政府补助、其他经营收入以及 IFRS/CAS 调节；
6. 晶圆代工、成熟制程和需求周期；
7. 中芯北方 49% 股权交易、NSI 交易、子公司及合并范围变化、会计政策或重述事件；
8. 任何与 D1-D7 直接相关的其他材料。

“尽可能获取更多数据”不得改变主研究问题。行情、估值、一致预期、目标价、同行比较和一般新闻只有在与上述采集目标直接相关时才可登记，且不因被采集而自动进入 D1-D7 分析。

### FR-015 目标映射与停止条件

- 每份快照材料至少映射一个 `acquisition_target_id`；映射只说明“为什么采集”，不代表数据完整或已具备证据资格。
- 搜索顺序覆盖：发行人；监管/交易所；政府/官方行业；具名机构/数据；扩展 Web、媒体、转载、访谈和论坛。
- 在目标清单均已处理、官方与扩展搜索各完成一轮，并且一轮补充搜索没有发现新的目标相关唯一材料后，标记 `Search Saturation`。不设置材料数量上限。
- Search Saturation 仅表示本轮搜索达到停止条件，不表示目标 `COVERED`、数据完整或结论可回答；采集阶段不得使用 `COVERED/PARTIAL` 冒充证据覆盖判断。
- 采集阶段的 gap 只记录搜索/材料不可获得、Candidate Holding 待确认和材料不可解析。事实 UNKNOWN、证据不足与结论缺口由后续阶段产生。

## 8. 上下文治理与轻量 RAG

### FR-020 先治理后规整

上下文治理只对当前快照中可解析、与 Acquisition Target 相关的 `ACQUIRED_UNASSESSED` 材料，根据主研究问题、主题和定位筛选候选片段，再由规整阶段提取事实，以减少对无关全文做技术和会计处理的工作量。该阶段不判断真实性、信源等级、内容类型、证据资格或冲突裁决。

### FR-021 片段定位

每个 `chunk_id` 必须回溯到 `material_id`，并尽可能保存页码、章节、表格、段落或数据行等 Content Locator 及片段哈希。分块不得丢失数字对应的表头、单位、期间和脚注。

### FR-022 轻量 RAG

- 只索引当前冻结快照中可解析、与 Acquisition Target 相关的 `ACQUIRED_UNASSESSED` 材料；
- 关键词/BM25 是必需基线；
- Embedding 或混合检索仅在 BM25 为 WARN 且预登记具体词法漏召回时允许同集实验；部分改善可以记录，但只有将 WARN 转为 PASS 且硬指标不退化时才进入 Demo；
- 本地索引必须可删除并从权威材料重建；
- 检索结果只是候选上下文，不能直接成为事实或证据；
- 检索相关性分数不表示信源可信度或证据强度；
- 记录固定查询的命中 `chunk_id`、定位准确性和已知漏召回。

不得建设向量数据库服务、长期知识库、增量同步、重排服务或检索 API。

## 9. 技术标准化与会计规整

这两部分由同一个 `normalize-research-facts` Skill 承担，但在内部保持先技术标准化、后会计规整两个明确步骤和转换轨迹。

### FR-030 技术标准化

每项数值事实必须分开保存：主体、指标、数值、单位、币种、缩放因子、期间/时点、报告类型和原文定位。标准化必须：

- 统一机器可读日期、单位表达和数值缩放，但保留原始值；
- 区分百分比变化与百分点变化；
- 区分期间数与时点数；
- 区分年度、累计期、单季度和 TTM；
- 保存币种转换的汇率来源、日期和公式；无合格汇率时不转换；
- 保存派生公式及全部输入 `fact_id`；
- 不对缺失单位、期间、币种或范围做猜测。

产能、出货、利用率和 ASP 必须保留晶圆计量口径与时间/测量基准。实体 8 英寸、实体 12 英寸和 8 英寸等值片不得自动换算；月产能、期末产能和季度平均产能不得混用；利用率不得由产能和出货反推。来源披露 ASP 与收入除以出货量得到的隐含 ASP 分别保存，后者只在主体、期间、业务范围、币种和晶圆口径完全一致时派生。

制程和应用结构保留来源分类、分母和分类体系版本，不同分母不得比较或合计，只允许固定显式分类映射。分类合计核验仅适用于计算前已由材料结构或固定规则确认同分母、互斥且完整的集合；不得以合计接近 100% 反推核验资格，不满足时为 `CHECK_NOT_APPLICABLE`。分类体系变化标记 `TAXONOMY_CHANGE`。

已发生资本开支、购建资产现金流支出、承诺金额、计划/指引和具体项目投资属于不同指标，不得自动合并或替代。规整阶段不判断资本开支是否已转化为产能、收入、效率或利润。

文本命题必须保留完整原文跨度、说话人/发布主体、时点和目标期间；任何拆分都必须携带原文中的否定、条件、不确定性和适用范围，无法无损拆分时保持一条。定性或条件陈述不得转换为自造数值或确定事实，`claim_type` 继续为 `UNASSESSED`。

记录级 `normalization_status` 为 `PASS|PARTIAL|BLOCKED`：PARTIAL 只表示来源可安全保存但部分规整属性未知，BLOCKED 表示特定映射、比较、转换、派生或桥接不能安全完成。运行级 `normalization_run_status` 按 `FAIL > WARN > PASS` 汇总；定位、哈希、契约、ID、转换轨迹或确定性错误为 FAIL，目标记录存在 PARTIAL/BLOCKED 或规整 gap 为 WARN，其余为 PASS。该状态不表示事实或证据资格。

规整阶段可以保存非权威的内容类型提示，但 `claim_type` 必须保持 `UNASSESSED`；最终内容类型、信源等级和证据资格由证据治理阶段确定。

### FR-031 主会计口径

- 主分析口径：IFRS、合并报表、USD。
- CAS 只用于调节和差异解释，不建立第二套平行分析结论。
- IFRS/CAS 调节只按固定 `CAS_TO_IFRS` 方向复算；基础值、调整明细、小计和目标必须显式区分，只有调整明细参与求和，且保留来源符号、加减方向和规范带符号金额。
- 桥接前必须匹配指标定义、权益归属、主体/合并范围、准则角色、币种/单位、报告版本/重述基础；流量指标须完全同期间，时点指标须完全同一 `as_of_date`。
- 桥接复算是附着于目标事实的核验记录，不是新的来源事实。差异为零时通过；非零差异按全部输入和目标的披露精度计算固定容差，容差内只警告舍入差异，超出时报公式不匹配；精度不足且存在非零差异时为 UNKNOWN。桥接失败不得删除或改写来源记录。
- 保留原始币种与缩放；转换必须有来源、日期和公式。
- 审计/未经审计状态、合并范围、报表版本和重述必须显式记录。
- 关键字段不完整时，该记录不得用于可比计算。

### FR-032 经常性经营盈利能力指标组

“经常性经营盈利能力”不是单一自造指标，按以下指标组解释：

1. IFRS 毛利率；
2. 报告 IFRS 营业利润率，即 `profit from operations / revenue`；
3. 只有调整项经确认、可分离、可追溯时才计算规整营业利润率，否则为 UNKNOWN；
4. 公司披露 EBITDA 利润率标为 `NON_IFRS`，经营现金流利润率和归母利润率仅作交叉核对或桥接，不替代营业盈利能力。

任何规整结果必须显示“报告值 -> 调整项 -> 规整值”的桥接。

### FR-033 调整规则

- 政府补助同时展示报告口径和剔除政府资金影响的敏感性口径；不得自动认定为一次性。
- 折旧与研发不得因影响利润而自动剔除。
- 其他调整项只有在正式材料可分离、能够重算且得到业务确认时才可纳入；否则为 TBD。
- 不得用“非经常性”标签替代逐项来源与公式。

### FR-034 期间和派生规则

- 年度、累计期、单季度和时点数据不得混为同序列。
- 只有会计准则、范围、单位、币种、审计/版本和指标定义一致时，才可用累计数相减得到单季度，并新建 `record_kind=DERIVATION`、`derivation_type=YTD_DIFFERENCE` 的记录；Ticket 04 再确定最终 `claim_type`。
- 不做机械年化。
- TTM 只允许由四个可比单季度组成。
- 资产负债表项目按时点解释，现金流项目按期间解释。
- 重述值优先参与当前可比分析，但原版本与差异必须保留。
- 重述关系只在发行人于 `as_of` 前明确说明时建立；多次明确重述以最新版本作为会计比较优先值，但所有版本及关系均保留。仅有数值差异而无明确重述说明时标记 `VERSION_CONFLICT` 和 gap，不自动选值；会计比较优先不等于证据资格。
- 发生重大范围或口径断裂时标记 `COMPARABILITY_BREAK`，不得强行连线。

## 10. 信源治理与确定性核验

### FR-040 信源等级

信源等级只能由 `govern-and-validate-research-evidence` 在材料已采集、解析和规整后确定，采集、上下文治理和规整阶段不得预判。

| 等级 | 定义 | 默认用途 |
|---|---|---|
| T1 | 可定位的原始/一手来源：监管披露、官方数据、公司正式材料或原始发言 | 可作为事实或来源观点的主要材料，仍需分类与核验 |
| T2 | 具名机构且方法、口径或数据血缘较透明的数据/研究 | 可作为独立支持或补充 |
| T3 | 可归属的二手分析，但方法或来源链不完整 | 仅作有限支持、解释或线索 |
| T4 | 聚合、转载、匿名或无法核验的专家笔记 | 只作发现线索，不支撑承重发现 |

信源等级表示原始程度和可追溯性，不表示内容必然真实，也不是投资置信度。同源转载必须归为同一来源组，不能以数量投票制造多源确认。

### FR-041 内容类型

`govern-and-validate-research-evidence` 必须把每项事实或声明最终分类为以下一种：

- `REPORTED_FACT`
- `DERIVED_METRIC`
- `MANAGEMENT_ASSERTION`
- `MANAGEMENT_GUIDANCE`
- `THIRD_PARTY_VIEW`
- `ANALYTIC_INFERENCE`

管理层指引、第三方预测和分析归纳不能伪装成已报告事实。

### FR-042 冲突处理

冲突按固定次序处理：

1. 先确认主体、指标、期间、单位、币种、范围和会计口径是否可比，必要时先规整。
2. 检查当前使用边界、`as_of` 和精确定位；不合格记录不得参与裁决。
3. 合并同源转载和伪多源。
4. 对事实冲突依次优先：重述值高于旧版本；经审计高于未经审计；法定披露高于演示材料、采访和二手资料；T1 高于 T2。T3/T4 的数量不能推翻高等级事实。
5. 管理层或第三方观点保持为观点，不用事实优先级把观点改写成事实。
6. 会随时间变化的观点保留各版本；`as_of` 之前最新版本只代表当前版本，不抹除历史版本。
7. 禁止平均冲突值或静默选择。
8. 仍无法解决时标记 `CONFLICT_UNRESOLVED`，不得支撑承重发现。

### FR-043 确定性核验

`govern-and-validate-research-evidence` 统一负责最终 T1-T4、内容类型、同源/转载关系、冲突状态、隔离状态以及是否允许进入分析和支撑发现。核验至少覆盖：文件与内容哈希、`as_of`、Material/Content Locator、必需字段、单位/币种/期间、公式复算、来源使用说明、来源层级、同源组、冲突状态、隔离引用、ID 引用完整性和 RAG 定位准确性。核验输出 `PASS`、`WARN` 或 `FAIL`，并给出逐项原因。

## 11. 分析与固定框架评分

### FR-050 七个维度

| ID | 维度 | 需要回答的问题 |
|---|---|---|
| D1_PROFITABILITY_CHANGE | 盈利能力变化 | 统一口径后，盈利能力实际发生了什么可验证变化？ |
| D2_UTILIZATION_EFFECT | 产能利用率影响 | 利用率通过固定成本吸收等机制支持、拖累还是无法解释变化？ |
| D3_MIX_EFFECT | 制程/应用结构影响 | 制程与应用结构变化是否有证据影响售价、成本或毛利？ |
| D4_CAPEX_CONVERSION | 资本开支转化 | 资本开支是否已转化为可观察的产能、收入、效率或盈利贡献，同时带来何种折旧压力？ |
| D5_CYCLE_EXPLANATION | 周期解释 | 行业供需、价格和库存周期能解释多少变化？ |
| D6_NONCORE_EXPLANATION | 非核心因素解释 | 政府补助及其他非核心/不可比因素能解释多少变化？ |
| D7_SUSTAINABILITY_EVIDENCE | 可持续性证据 | 改善是否跨期、跨指标并有经营机制支持；哪些后续可观察指标在什么条件下会使其降级或推翻？ |

### FR-051 发现状态与证据分

每个维度分别输出：

- `finding`：`SUPPORTED`、`MIXED`、`NOT_SUPPORTED` 或 `UNKNOWN`；
- `evidence_score`：`0 UNSCORABLE`、`1 LIMITED`、`2 ADEQUATE` 或 `3 STRONG`。

约束：

- 分数表示支持该发现状态的证据强度，不表示公司好坏或投资质量；
- 高证据分可以对应 `NOT_SUPPORTED`；
- 分数 0 必须对应 UNKNOWN；
- 每项都要列支持证据、反证、替代解释、限制和 gap；
- 不生成加权总分、综合星级或投资评级。

报告汇总为以下向量：

- `profitability_change`: D1
- `sustainability_support`: D7
- `driver_attribution`: D2-D4
- `alternative_explanations`: D5-D6
- `overall_score: NOT_APPLICABLE`

### FR-052 推理边界

- 只能引用状态允许且未隔离的 `evidence_id` 支撑发现。
- 相关性不得自动表述为因果关系。
- 同一经营变化不得在多个驱动中重复计算而不说明交叉影响。
- 找不到独立证据时，应把管理层解释保留为 `MANAGEMENT_ASSERTION`，不能升级为验证后的原因。
- 结论必须能被新证据修订；不能用肯定语气掩盖 UNKNOWN、冲突或可比性断裂。
- D7 的后续观察条件必须对应可追溯指标和明确判定逻辑；数值阈值只有在冻结数据、已确认规则或可复算公式支持时才能给出，否则记录为 UNKNOWN/TBD，不得由模型编造。

## 12. 反方质询

### FR-060 四类质询

1. 来源与溯源：承重证据是否真实存在、可定位、`as_of` 合格且没有伪多源。
2. 会计与可比性：准则、期间、单位、范围、重述、政府补助和派生计算是否可比。
3. 归因与因果：是否把相关性当因果、重复归因或忽略反向机制。
4. 证伪与缺证：哪些反证、缺失数据或后续可观察条件会使发现降级或被推翻。

质询对象必须是明确的 `finding_id` 或 `evidence_id`，不能进行泛化的“看多/看空”辩论。

### FR-061 质询回路

- 第一版分析完成后才进入质询。
- 被质询方只能使用冻结快照内、发布时间不晚于 `as_of` 的材料。
- 允许处置：`RESOLVED_NO_CHANGE`、`RESOLVED_WITH_REVISION`、`UNRESOLVED_DOWNGRADED`、`BLOCKING`。
- 每个问题只做一次定向复核；全流程最多两轮质询。
- 质询不能直接改写发现；编排器将修订请求返回责任阶段。
- `challenges.yaml` 必须保存修订前后版本与理由。
- 两轮后仍未解决的问题必须降级或标为 BLOCKING，并进入报告和 gaps，不得无限循环。

## 13. 报告生成

### FR-070 固定报告结构

`report.md` 按以下顺序生成：

1. 案例、`as_of`、快照、治理状态与分发状态；
2. 数据覆盖与来源覆盖；
3. 报告口径与规整口径下的盈利能力变化；
4. D2-D4：利用率、结构和资本开支驱动；
5. D5-D6：行业周期、政府补助和其他替代解释；
6. D7：可持续性支持、降级与证伪条件；
7. D1-D7 发现和证据分向量；
8. 反方质询与修订；
9. 冲突、UNKNOWN、TBD、隔离项和数据限制；
10. 来源、公式、会计口径和溯源附录。

### FR-071 数字与来源

报告中每个数字必须同时显示或可直接链接到：

- 来源名称和原始定位；
- 发布时间；
- 数字对应的期间或时点；
- 单位、币种和缩放；
- 报告/派生/敏感性口径；
- 对应 `evidence_id`，派生值还需公式和输入。

同一句出现多个数字时，不得用一个模糊脚注掩盖来源或期间差异。

### FR-072 发布门槛

本 Demo 不发布，因此采用低门槛内部输出：

- 固定 `distribution_status=INTERNAL_DEMO_ONLY`；
- 不设最低证据分，始终生成内部诊断报告；
- 独立显示 `governance_status=PASS/WARN/FAIL`；
- FAIL 时必须显著说明不可用范围，隔离数据不得支撑发现；
- 人工复核默认为 `PENDING_HUMAN_REVIEW`；
- 不生成 PDF、网页、Dashboard、API 或其他外部分发格式。

### FR-073 禁止输出

系统不得输出买入、卖出、持有、仓位建议、目标价、估值锚、投资吸引力判断或系统自己的盈利预测。来源中的管理层指引、分析师预测或目标价如因溯源需要出现，只能作为具名、带时点的来源观点；目标价和估值内容不进入主分析或评分。

## 14. UNKNOWN、TBD 与人工复核

### FR-080 缺口规则

- 事实、数值或结论因当前材料不能确定：UNKNOWN。
- 规则、来源边界或业务决定待指定角色确认：TBD。
- 每项必须写入 `gaps.yaml`，包括 `gap_id`、`origin_stage`、`gap_kind`、问题、影响、确认人、所需证据、优先级和状态。
- 采集阶段只能产生 Acquisition Gap：搜索/材料不可获得、Candidate Holding 待确认或材料不可解析；不得在采集阶段提前创建事实 UNKNOWN 或证据不足结论。
- 不得用“待补充”自由文本代替结构化 gap，也不得构建通用 Gap 服务。

### FR-081 人工反馈

在真实人工复核发生前，只能记录 `PENDING_HUMAN_REVIEW`。不得虚构专家姓名、评语、批准或共识。人工意见产生后，应保留原发现、反馈和处置，不静默覆盖。

## 15. 数据契约与规则管理

### FR-090 固定文件

权威产物、格式和 ID 链以 [契约地图](../../contracts/contract-map.md) 为准。配置/汇总使用 YAML，逐条记录使用 JSONL，报告使用 Markdown。CSV 如存在仅为派生视图。

### FR-091 单一规则来源

会计、信源、评分、质询和报告规则各只有一个权威定义。Skill 文件解释职责并引用规则版本，不复制规则全文；脚本读取同一规则。不得实现规则 DSL、动态权重或插件式规则加载。

### FR-092 版本与重现

黄金案例必须能从 `case.yaml`、冻结快照、规则版本和权威文件哈希识别。材料、元数据或规则变化要产生新快照/产物哈希，不能静默改写后继续声称是同一黄金案例。

Snapshot v1 `smic-4c110e93f810aa8e`、v2 `smic-95dcd12eba2fe17c` 和当前 v3 `smic-a283e95e2c9e8068` 均保持不可变。v3 完整列出自己的材料和冻结文件，并能脱离 v1/v2 独立完成 `DEMO_RUN`；`parent_snapshot_id` 仅用于血缘说明。下游阶段不得把信源等级、冲突、隔离或证据资格写回任何冻结快照。

## 16. 验证要求

### VR-001 Skill 触发

编排器至少使用 3 个应触发问题和 3 个不应触发问题验证范围识别。内部阶段 Skills 使用固定契约 fixtures 验证输入缺失、非法状态和正常路径；不为每个 Skill 建设独立评测平台。

### VR-001A Snapshot v3 采集边界

至少验证：

1. Snapshot v1 身份、清单和冻结文件哈希完全不变；
2. 低可信、匿名、转载及当前不可解析但满足最低门槛的目标相关材料可以 `ACQUIRED_UNASSESSED` 进入新版本快照，且不会自动进入分析；
3. 已确认发布时间晚于 `as_of` 的材料被排除；发布时间窗口跨越 `as_of` 或缺失最低可追溯元数据的候选进入 Candidate Holding Area；
4. 缺少条款 URL、`usage_basis` 或 `restriction_status=USABLE` 不阻塞采集；
5. 完全相同内容哈希只产生一个材料记录和一份冻结文件，并保存 Canonical/Alternate Material Locators；
6. 每份材料映射 Acquisition Target，采集阶段不输出 `COVERED/PARTIAL`；
7. Search Saturation 必须有目标清单、搜索渠道和最后一轮无新增目标相关唯一材料的记录；
8. `DEMO_RUN` 在不联网的情况下接受 `ACQUIRED_UNASSESSED`，只校验快照身份、哈希、`as_of` 和最低元数据。

### VR-002 黄金案例端到端

Snapshot v3 黄金案例必须验证：

1. `DEMO_RUN` 不访问实时数据且拒绝 `as_of` 越界材料；
2. 任一报告数字能追溯 `evidence_id -> fact_id -> chunk_id -> material_id`；
3. 派生指标可由记录公式复算；
4. 同源转载不增加独立证据数量；
5. 一个无法解决的事实冲突会被隔离并使相关发现降级；
6. 缺失必需数据产生 UNKNOWN 和 gap，而不是虚构值；
7. 政府补助同时展示报告与敏感性口径，且不自动标成一次性；
8. D1-D7 均有合法状态和证据分，`overall_score=NOT_APPLICABLE`；
9. 质询最多两轮，保留修订前后；
10. 即使治理 FAIL 仍生成带显著警示的内部诊断报告；
11. 报告无交易指令、仓位建议、目标价锚或系统预测。

### VR-003 RAG 小型核验

使用与 Snapshot v3 和查询规则版本绑定的 locator 级 `MUST_HIT`、`SHOULD_HIT`、`NEGATIVE_CONTROL` 固定标注集。每个中英文子查询独立取 Top 20，同一材料最多 5 个直接命中；Query Family 按 `chunk_id` 合并且不二次截断，只有未被结构过滤的 `DIRECT_HIT` 计入验收。

`MUST_HIT Recall=100%`；`SHOULD_HIT Recall` 总体至少 80% 且每个有标注 Family 至少 60%；每个子查询 `Precision@min(5,N)` 至少 60%，`N=0` 时为 0；负控候选率为 0；关键 locator 与数字表头/单位/期间/脚注完整率为 100%；两次干净重建哈希一致。标注和 Precision 只判断主题相关性，不判断真实性或证据资格。

`retrieval_status=PASS|WARN|FAIL` 只表示检索质量；局部可界定的 FAIL 只阻断对应 Query Family，否则全局阻断。可选检索方案的部分改善可以保存为实验记录，但只有在相同固定集合上把 BM25 WARN 转为 PASS 且不降低关键召回、负控、定位和确定性指标时才进入 Demo。

### VR-004 不建设评测平台

验证使用本地 fixtures、简单脚本和黄金案例记录即可。不得新增在线评测服务、标注平台、长期指标库或为未来多案例预建测试框架。

## 17. 验收标准

### AC-001 文档与边界

- `AGENTS.md` 包含 Demo 简洁性约束。
- `CONTEXT.md` 使用已确认术语，且不出现通用 Research Run/Stage Artifact 领域模型。

### AC-002 最小实现形态

- 仅有八个确认的 Skills、集中脚本、单一规则来源和固定案例文件。
- 不含通用工作流、连接器平台、数据库、前后端、发布系统或未来产品抽象。
- 每个新增组件能对应本 Spec 的当前 FR/VR/AC。
- 按 [Demo 范围](../../docs/product/demo-scope.md) 的“黄金案例优先与架构克制”执行：不影响黄金案例硬验收的局限优先记录为限制或 gap，不为增强假设场景鲁棒性增加通用架构。

### AC-003 数据与溯源

- Snapshot v1/v2 保持不可变；Snapshot v3 是带新身份、`as_of`、哈希和完整材料清单的自包含当前快照。
- v3 内材料统一为 `ACQUIRED_UNASSESSED`；采集目标映射不冒充数据完整性或证据覆盖，最终使用资格由证据治理决定。
- 高相关但最低元数据不足的候选保存在 Snapshot 外的 Candidate Holding Area，不能提前获得材料/证据身份。
- 每个进入分析的数字保留来源、时点、期间、单位、口径和定位。
- ID 链可从报告发现追溯到原始材料。
- UNKNOWN/TBD、冲突和隔离状态不会被默认值覆盖。

### AC-004 会计与证据治理

- 主口径为 IFRS/合并/USD，CAS 只作调节。
- IFRS/CAS 桥接方向、行角色、符号和期间/口径匹配规则固定；复算容差来自披露精度，局部核验结果可解释 PASS/WARN/FAIL/UNKNOWN。局部失败只使桥接 BLOCKED、规整运行至少 WARN，不污染来源事实或直接冒充运行级 FAIL，且不引入通用对账引擎。
- 产能/出货/ASP、结构占比和资本开支使用固定可追溯口径，不做无来源换算、跨分母合计或因果推断；文本命题拆分不丢失限定语义。
- 规整记录的 PASS/PARTIAL/BLOCKED 边界固定，运行状态按 `FAIL > WARN > PASS` 确定性汇总且不冒充证据状态。
- 报告值、调整项和规整值有明确桥接。
- 政府补助按双口径敏感性呈现，折旧/R&D 不被自动剔除。
- 信源等级、内容类型、同源去重、冲突、隔离和证据资格均由 `govern-and-validate-research-evidence` 最终确定，不由采集或 RAG 相关性预判。
- 确定性核验结果能解释 PASS/WARN/FAIL。

### AC-005 分析、质询与报告

- 研究问题与流程完成状态分开表达。
- D1-D7 各自输出发现状态、证据分、支持、反证、替代解释和缺口，无总分。

- 报告仅供内部 Demo，不含禁止输出。
