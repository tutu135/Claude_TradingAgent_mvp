2. 续跑机制：单轮上下文不足时，在该轮结尾输出"进度清单"（已完成文件 / 未完成文件 / 下一步从哪里继续），等待用户回复"继续"后接着执行，不要重复已完成的内容。

二、工作原则

1. 只依据当前能够读取的真实材料，不得根据通用金融知识编造内部数据、API 或字段。
2. 不确定的信息统一标记为 UNKNOWN 或 TBD，并说明需要由谁、通过什么材料确认。
3. 每个数据源、字段和 API 尽可能标注来源文件、文档日期、章节或系统名称。
4. 不输出任何 API Key、密码、Cookie、Token、数据库密码、个人账号或真实访问凭证。只记录鉴权方式和环境变量名称。
5. 对涉及个人信息、持仓、交易记录、重大未公开信息或其他敏感内容进行脱敏，只保留完成系统设计所需的结构和字段。
6. 对 Wind、iFinD、Choice、Bloomberg、券商研报库等受许可约束的数据，不批量复制原始数据；只输出数据目录、字段、调用方式、权限边界和脱敏样例。
7. 股票池、组合或持仓数据只登记是否存在、字段和权限，不输出真实持仓明细，除非用户另行明确授权。
8. 不要因为资料不完整而停止。先完成可确认部分，再生成缺失项和补充问题清单。

四、第二步：生成完整数据清单

逐类盘点系统实际可以使用的数据。至少检查以下类别；没有的数据也要保留该类别并标记"当前未发现"，不要直接删除：

1. 证券主数据：股票代码、公司名称、上市地、交易所、行业分类、上市状态、股本等。
2. 行情数据：开高低收、成交量、成交额、换手率、复权价格、波动率、区间收益等。
3. 估值数据：PE、PB、PS、EV/EBITDA、市值、历史分位、可比公司估值等。
4. 财务报表：收入、归母净利润、扣非净利润、毛利率、费用率、现金流、资产负债等。
5. 盈利预测与一致预期：收入、利润、EPS、评级、目标价、机构数、预测版本和调整幅度等。
6. 公司经营指标：订单、产能、产能利用率、销量、出货量、单价、库存、客户结构、产品结构等。
7. 行业指标：价格、产量、销量、库存、开工率、渗透率、资本开支、景气指标等。
8. 公司公告与监管披露：财报、重大事项、回购、增发、股权变化、澄清公告等。
9. 研报：券商研报、行业深度报告、海外投行报告、独立研究等。
10. 电话会、路演和调研纪要：管理层陈述、分析师问题、经营指引、订单、价格和风险等。
11. 新闻、政策和行业事件：新闻正文、官方政策、行业大会、公司官网更新等。
12. 产业链与跨市场数据：供应关系、供应占比、上下游、海外可比公司、映射依据和不可比点等。
13. 历史投资研究报告：单标的、赛道、对比、财报点评、事件点评和跟踪报告。
14. 历史交互与反馈：用户问题、模型回答、人工修改、批注、评分、采纳情况和错误类型。
15. 假设、复盘和跟踪记录：研究假设、关键变量、证伪条件、复查日期、兑现或证伪结果。
16. 股票池、组合或持仓数据：只登记是否存在、字段和权限。

为每个数据源生成 data-inventory.csv，每行一个数据集、数据表、文档库或 API。字段至少包括：

- data_source_id
- 数据源名称
- 数据类别
- 提供方或来源系统
- 业务用途
- 数据类型：结构化、指标型、半结构化、文本、图片、音频或视频
- 数据格式：API、数据库表、Excel、CSV、JSON、PDF、Word、PPT、HTML、TXT、音频等
- 接入方式
- 数据规模：记录数、文件数、容量、公司数或行业数
- 时间范围
- 更新频率
- 数据延迟
- 历史版本是否保留
- 数据质量情况
- 主要权限限制
- 是否允许模型读取
- 是否允许缓存
- 是否允许保存派生结果
- 是否允许导出或再分发
- 是否可以提供脱敏样例
- 负责人或确认人
- 当前状态
- 待确认问题

五、第三步：细化到字段、指标和数字口径

对结构化和指标型数据源，生成 data-dictionary.csv，每行只能描述一个实际字段或指标。不要只写"财务指标""行情数据"等大类。非结构化资料（研报、公告、纪要等）不套用此表，按本节末尾的 unstructured-catalog.csv 单独登记。

每个字段至少填写：

- data_source_id
- 表名、接口名或文件类型
- 字段英文名
- 字段中文名
- 字段类型
- 字段说明
- 示例值，必须脱敏
- 单位
- 币种
- 主键或定位字段
- 股票、公司、行业的标识方式
- 时间字段含义
- 发布日、报告期、交易日或采集日的区别
- 更新频率
- 空值含义
- 枚举值
- 是否原始字段或派生指标
- 派生公式
- 行情口径：前复权/后复权/不复权、交易日历、停牌处理、是否含盘前盘后
- 财务口径：归母/扣非、单季/累计/TTM、母公司/合并
- 估值口径：市值口径（总市值/流通市值/自由流通市值）、估值日期
- 经营口径：总收入/分部、国内/海外、主营/贸易/代理
- 可比口径：as_reported、restated、pro_forma
- 预测口径：单家预测/一致预期、样本机构数、统计方法、预测期、预测版本日期；目标价一律登记为观点类数据，不作事实
- 审计状态
- 定义是否发生过变化
- 来源等级或权威性
- 数据质量问题
- 允许用途
- 禁止用途
- 备注

重点检查以下容易出错的数字：

- 年报数字是否被用于代表当前季度经营状况；
- 单季与累计是否混用；
- 归母与扣非是否混用；
- 母公司与合并报表是否混用；
- 公司自定义指标是否被当成审计指标；
- 并表、出表、资产注入或剥离是否造成表观增速失真；
- 基本 EPS 与摊薄 EPS 是否混用；
- 毛利率、产能和产能利用率的定义是否一致；
- 行情是否前复权、后复权或不复权；
- 披露日、首个交易反应日和数据采集日是否混淆；
- TTM 与年度、单季数字是否混用；
- 总市值、流通市值与自由流通市值是否混用；
- 单家预测与一致预期是否混淆；
- 目标价和研报预测是否被错误当成事实。

对非结构化资料（研报、电话会/路演/调研纪要、公司公告、新闻、历史投资报告、历史交互与反馈），不套用字段字典，改为生成 unstructured-catalog.csv，每行一类资料库，至少填写：

- data_source_id
- 资料类型
- 基础元数据字段：如标题、机构、作者、日期、覆盖标的/行业、评级、会议类型、参会人、公告类型等
- 重要内容字段：如摘要、核心观点、盈利预测、Q&A、管理层陈述、公告正文、表格等
- 可提取信息：如投资逻辑、目标价、关键假设、经营指引、订单变化、重大事项、财务影响等
- 原文形态与定位方式：研报能否同时提供 PDF 原文和结构化目录；电话会如只有录音，是否有转写文本；公告是否有原文链接或公告编号；历史报告是否保留初稿、修改意见与终稿的对应关系
- 数量、时间范围和更新方式
- 权限与脱敏要求
- 备注

六、第四步：整理所有 API 和工具合同

生成 api-catalog.yaml。每个实际存在的 API、数据库查询工具、文档检索工具或内部服务分别记录：

- provider
- tool_name
- 功能说明
- 适用任务
- 禁止用途
- 接口协议或 SDK
- 鉴权方式，只写方式和环境变量名，不写真实凭证
- 席位归属与调用边界：席位或账号属于谁、是否允许服务器端程序调用、是否仅限终端人工使用、并发或用户数限制
- 请求参数名称、类型、必填性和示例
- 返回字段名称、类型、单位和含义
- 时间字段与时区
- 数据口径
- 分页方式
- QPS、日限额和并发限制
- 超时和重试策略
- 常见错误码
- 空数据语义
- 权限错误处理
- 数据更新延迟
- 缓存许可
- 派生结果存储许可
- 原始数据导出限制
- 成功响应脱敏样例
- 空数据脱敏样例
- 权限失败样例
- 限流样例
- 字段变更样例：历史上发生过的字段名或口径变更实例；未发生过则标注"未发生"
- 文档来源和版本日期
- 当前是否可调用
- 接入前待确认事项

如果当前只能看到 API 产生的数据、但看不到正式 API 文档，请从实际调用样例中归纳"候选合同"，并明确标记 inferred=true，不能写成已确认合同。

对文档型数据源（研报库、公告库、纪要库、新闻库）的检索接口，返回合同必须包含文档定位字段：文档 ID、标题、发布者、发布时间、页码、段落或表格坐标、原文链接或对象存储指针。下游系统的溯源链依赖这些字段；不具备定位能力的接口，在接入前待确认事项中注明。

七、第五步：以示例股票产出数据切片（强制验收项）
