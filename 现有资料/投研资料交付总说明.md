# 投研资料交付需求 · 总说明（发给甲方）

> 本文档是给甲方负责人看的总说明，不需要发给模型。实际执行时使用配套的两份 Prompt 文件：
>
> 1. **《投研数据交付Prompt.md》** —— 交给能访问贵方数据系统、数据字典、API 文档的模型；
> 2. **《投研流程与经验交付Prompt.md》** —— 交给能访问贵方历史报告、历史对话、批注记录、SOP 的模型。
>
> 这两个文件**通篇即 Prompt 正文**，无需摘取片段——把整个文件的全部内容复制发给模型即可。两份可以在同一环境先后执行，也可以由不同的人在不同环境分别执行。

---

## 一、我们需要什么

为建设投研 AI 系统，我们需要贵方交付两个资料包：

**数据资料包**（由数据 Prompt 产出）：
1. 数据资产清单：有哪些数据源、规模、权限、更新方式；
2. 字段与口径字典：每个字段的单位、时点、会计口径；
3. API 与工具合同：每个接口的请求、响应、限流、权限边界；
4. 以一只示例股票为样本的数据切片：该股票在每类数据下、许可范围内的真实取数结果（仅用于系统设计验证，不作再分发）。

说明：第 3、4 项是在《投研AI项目需求报告》基础上细化的要求——接口合同要细到工程团队能直接写数据接入代码，数据切片让工程团队看到每类数据的真实形态，而不只是字段定义。

**流程与经验资料包**（由流程 Prompt 产出）：
1. 真实人工投研流程（SOP）：从接到问题到报告复核的每一步；
2. 专家判断经验：看什么指标、怎么裁定冲突、常见错误与纠偏；
3. 报告样例与评价标准：什么算合格、优秀、不可接受；
4. **一个单股票全链路案例**：以同一只示例股票为例，完整重放"用了什么数据、每一步怎么处理、在哪里做了什么判断、报告怎么形成、如何复核"；
5. **一个投研方法论 Skill**：把贵方的方法论、任务流程、判断规则、报告标准打包成我们的模型可以直接安装使用的技能包。

其中第 4、5 项是本次交付的核心：**投研方法论只存在于贵方**，我们的工程团队没有投研经验，无法替贵方补写任何业务规则。案例和 Skill 是这些经验唯一可执行的载体。

**此外还需要一项不经模型的安排**：1–2 位业务专家的沟通机会（对应《投研AI项目需求报告》最小资料包第 6 项）。两个资料包中所有标记为"待确认"的规则和缺口，最终需由专家确认；模型产出的 gaps-and-questions.md 可直接作为这次沟通的议程。

## 二、为什么以 Prompt 方式交付

贵方的投研流程与资料沉淀主要依托模型工具（历史对话、批注、报告都在模型可访问的环境里）。与其由人工逐项填表，更高效的方式是：把两份 Prompt 分别发给贵方能访问相应资料的模型，由模型完成盘点、结构化和脱敏，贵方复核后回传。人工只需要做三件事：选环境、附材料、复核产物。

## 三、安全边界（我们承诺，Prompt 中也已写入约束）

- 不需要任何 API Key、密码、Cookie、席位凭证——只要鉴权方式和环境变量名；
- 不需要持仓明细——只登记是否存在、字段结构和权限；
- Wind/iFinD/Choice/Bloomberg 等授权数据，只要字段结构、权限说明和少量样例，不要批量原始数据；示例股票的数据切片仅取许可范围内的少量真实数字，用于系统设计验证，不作再分发；
- 涉及个人信息、重大未公开信息的内容，脱敏或标记后不外传；
- 产出物不含任何买卖建议。

## 四、执行步骤

### 第 1 步：确定示例股票（两份 Prompt 用同一只）

选一只贵方覆盖较深、数据相对完整、有近期财报或事件的半导体 / AI 产业链标的，填入两份 Prompt 开头的【示例股票】处。两份 Prompt 使用同一只股票，这样数据切片和流程案例可以互相对上。留空则由模型按 Prompt 内规则自选。

### 第 2 步：选择模型环境

每份 Prompt 各自选择能访问对应资料的环境：

- **数据 Prompt** 需要的环境：能读到数据源列表、数据字典、API 文档或脱敏调用记录；
- **流程 Prompt** 需要的环境：能读到历史报告（含优秀与失败样例）、历史模型对话、人工批注、SOP、报告模板。

两种模式均可：带文件工作区的模型（推荐，直接产出目录和文件）；纯聊天界面的模型（Prompt 内置降级模式，以文件分隔块形式输出）。

### 第 3 步：准备附件材料

**随数据 Prompt 提供**（缺项不阻断，模型会记入缺口清单）：
1. 数据源或系统列表；
2. 数据字典（如有）；
3. API 文档或脱敏的调用记录；
4. 三份产品文档 PDF（帮助模型理解接收方用途，可选）。

**随流程 Prompt 提供**：
1. 3–5 份贵方认可的高质量投研报告；
2. 1–3 份质量一般或存在错误的报告；
3. 上述报告对应的原始输入或数据来源；
4. 完整的历史对话或人工批注记录；
5. 一位分析师完成真实任务的过程记录或访谈转写；
6. 现有 SOP、检查清单、报告模板（如有）；
7. 三份产品文档 PDF（可选）。

### 第 4 步：执行顺序与多轮续跑

建议先跑数据 Prompt、再跑流程 Prompt（流程案例可以引用数据包中登记的 source_id）；并行执行也可以。产物较多，单轮上下文可能不够——模型会在每轮结束输出进度清单，回复"继续"即可续跑。

### 第 5 步：复核并回传

- 工作区模式：将两个产出目录（`investment-research-data-handover/` 与 `investment-research-process-handover/`）分别打包回传；
- 纯对话模式：将模型输出的全部文件分隔块汇总保存后回传；
- 回传前请贵方负责人快速复核：无凭证泄露、无持仓明细、脱敏到位、缺口清单与实际相符。

## 五、验收标准

- **数据包**：我们的工程团队照着它就能写数据接入代码——每个字段有单位、时点、口径；每个 API 有请求、响应、限流、错误处理。
- **流程包**：每条规则能落进配置、能写成测试用例；单股票案例中每个承重数字和论断都能回到具体来源；Skill 可以直接安装到我们的模型环境中触发使用。
- 单股票全链路案例是强制验收项：只有一份最终报告、没有输入清单、证据索引、执行轨迹和判断记录，视为未完成。
