投研系统 · 产品说明⽂档(双产品)
背景:这是给⼀家私募做的投研系统的产品说明。系统由两个物理隔离的产品组成——主系统(投研引擎)
和瞭望塔(信息雷达)。本⽂据近期⼀次产品评审讨论整理。
关键设计原则(全⽂据此展开):
主系统以"纪律"为核⼼:每个进⼊判断的数字都带来源、带⼝径、过反⽅质询;凑不⻬就不输出,系统不下买
卖指令。⾯向普通⽤户的版本可以放低对完成度的预期,但核验标准不放松。
瞭望塔只看不判断:采集、去重,给每条出⼀句中性摘要,不分级、不判多空、不显示价格。
全球视野并⼊取数:产业链图谱、跨市场对标、异动监测这些"全球视野"的内容,作为⼀条带特定信源和规
则的检索通道并⼊主系统取数,和 A 股数据⾛同⼀套治理,不再单列成⼀层。
⾸期(MVP,最⼩可⽤版本)聚焦三类问题:单标的、赛道、两标的对⽐;领域先做半导体与 AI ;⼀问产出⼀份
报告;数据实时取,不做缓存、多模态、追问。
阅读顺序:总览 → 主系统 → 瞭望塔 → 两产品边界 → 分⼯与待确认项。

⼀、产品⼀:主系统(投研引擎)
1.1 产品定位
做什么:给定⼀个标的(某只股票或公司)或赛道(某个⾏业细分,如光模块、HBM 内存),系统⾃上⽽下拆解问题,
多源取数据,再做上下⽂治理、会计⼝径规整、信源分级与溯源,按固定框架打分、做反⽅质询,最后产出⼀份
每个数字都带来源与时点、被反复挑过刺的结构化分析报告。
核⼼是报告的准确和全⾯，不是预测。系统不输出买卖指令,也不给可作锚的⽬标价,决策权留给⼈。
问题边界:
⽀持三类提问:单标的代码、赛道或主题、两标的对⽐。
领域先做半导体与 AI 。
越界或⽆关的问题(问其他类别的股票、问⽆关的问题),系统尽⼒回答,但会提前声明这是专业⼯具(半导体
与 AI 资本开⽀),不是通⽤聊天机器⼈。要不要扩到别的赛道,先看效果再说,因为每个⾏业的判断属性都不
⼀样。
有四道设计防⽌⽤户随便问导致失控:范围框死(只到标的或赛道、窄领域)、固定模板收敛(答案都填进同
⼀结构)、核验与问题⽆关(对所有问题⼀视同仁地核验)、答不上来就标"不可⽤"、绝不编。

1.3 贯穿性⼯程主线(决定报告质量的⼏件事)
把它当真正的产品做,光有模块清单不够。真正决定输出质量能不能控住的,是下⾯这⼏条贯穿全流程的⼯程主
线。
上下⽂治理
问题:底层只是数据库和信源,让 agent 随便查,喂进模型的上下⽂⻓度就不可控,输出质量也就不可控。⼀篇研
报不可能整篇塞进上下⽂,深度报告甚⾄ 100 多⻚⼀次塞不下。
做法:全流程都在做⼀件事——按问题把最相关的证据筛出来、压缩好,再喂给模型。两类技术路线,各有取舍,
按场景选:
路线 优点 代价 适⽤
RAG / 语义向量抓取(按语义把相关 快、省 token 有偏差、可能漏线索 追求速度、容错较⾼

多 agent 编排(⼀个 agent 处理完 召回好、可严 token 消耗⼤、延迟⾼(⼀份报告 追求"不漏线索"、可

深度报告专⻔处理:重磅深度报告通常两三个⽉才发⼀篇,单⽉最多七⼋篇,但往往最有价值。100 多⻚⼀次塞

析(时间和算⼒代价都不可接受)。它挂在抓取解析模块下,处理那些需要本地缓存的深度报告。

===== PAGE 6 =====
多 agent 编排
编排器不是单线程跑到底,⽽是⼀组分⼯的 agent 协作:有的负责把⼀篇报告⾥需要的内容筛选、压缩出来(简
单任务),有的负责在⼲净证据上出判断、产出整篇报告(复杂任务)。这套⾯向本场景的专⽤编排框架,是⼯程量
的重头之⼀。
模型路由
不同⼦任务派不同贵贱的模型:筛选、压缩⽤⼩模型(便宜、快),最终判断和出报告⽤最好的模型。模型可切换,
⾃⽤先⽤最好的,远期⾯向⼤众可降档省成本。要权衡延迟,模型越⼤延迟越⾼。
记忆与⾃进化
让系统能⾃进化:⽤记忆记下"⽤户这次提了什么反对意⻅、不该怎么做",随使⽤⽽改进。通⽤编排⼯具的记忆
是通⽤的,我们要做的是⾯向投研场景的垂直记忆,做更有针对性的优化。这是产品的独特价值之⼀,属于可扩
展、需要预留空间的能⼒,⾸期先把框架沉淀下来,后续持续迭代。
评测
产出好不好,是多维度的评价,不是单⼀指标:
硬指标:数据准不准、有没有漏掉该考虑的东⻄、有没有⼝径错、漏过滤、编数字。
软指标:⽤户的主观认可度,以及⽤户拿到产出后再追问、推翻观点的交互内容。这些交互本身也是评价的
⼀部分,可以回流到记忆⾥。
评测是⼀条持续打磨的路:不断让系统更准、更好⽤,⾸期不可能⼀步到位,需要持续迭代。
1.4 逐模块说明(M1–M12)
主系统按⼗⼆个模块组织,编号 M1 到 M12。下⾯逐个说明职责。
取数层
M1 编排器(总指挥):不是采集器,⽽是调度⼤脑。把⼀个⼤问题拆成⼦任务(套⽅法论框架展开成要取的维
度),决定调谁,最后拼成报告;取回结果再决定下⼀步,反复直到取够。技术上是⾃写的轻量⼯具调⽤循环,驱
动多个 agent 协作。AI 的灵活性集中在"怎么取",⽽"什么算⼀份完整分析"由⽅法论框架定死。
M2 抓取解析:爬公开信息,包括公告、财报 PDF、电话会、⾏业⼤会、研报、政策。
财报表格解析是整个项⽬最⼤的单点⼯作量,要求解析出的数值对着原⽂逐项核对、误差为零;格式乱、
跨⻚表、扫描件构成⻓尾。
深度报告索引:100 多⻚的深度报告(两三个⽉⼀篇、单⽉不超过七⼋篇)先拆分、建索引、本地存,按需
检索⽚段喂给上下⽂治理这⼀层,不每次从头解析。
多模态(后期,⾮⾸期):A 股⻅⾯会有时只有录⾳、没有⽂本,这类先做⾳视频转写再⼊库;美国公司的电
话会⽐较正规,通常已有⽂本。

===== PAGE 7 =====
M3 数据接⼝:封装甲⽅已经买好的三家⾦融数据终端(Wind、iFinD、Choice),统⼀成⼀个数据接⼝。所
谓"信息已有、只是在别的系统⾥",指的就是这块。海外研报、海外⼀致预期等也⼤多有接⼝。
web 检索:公开⽹络补充。
全球视野检索(M9/M10/M11):与通⽤ web 检索并列的⼀条独⽴取数通道,但限定特定信源和特定规则;产
出和其他通道⼀样强制向下过治理层。三块内容详⻅后⽂。
取证与上下⽂治理
这不是单独⼀个编号模块,⽽是贯穿取数和治理之间的⼯程环节:把取回的原始材料筛选、压缩、索引成"⻓度
可控、最相关"的证据,再交给治理层。⼀部分可以⽤程序做(脚本抓关键词、向量召回),⼀部分要 agent 处理
完再交给下⼀个 agent。
治理层(最关键的⼀层)
M4 ⼝径规整:只管让数字可⽐。强制每个数字说清⾃⼰按什么会计定义算出来(⺟公司还是合并、单季还
是累计、扣⾮还是归⺟……)。⼝径凑不⻬就把数字作废,绝不猜。这是纯机械活。
M5 信源治理与溯源:管置信度。给每条来源分五级(从 T1 ⼀⼿披露/原话,到 T4 低可信的聚合投研、专家
纪要;级别越低,越只能当线索⽽不能当事实),把洗稿、抱团的重复来源合并成⼀个,把观点从事实⾥分出
来、不让它冒充事实,对低可信内容做证伪质询,对疑似内幕信息(即重⼤未公开信息,交易它违法)标记、留
待⼈⼯合规复核,保证任何结论都能回链到原⽂。
承接全球视野的纪律红线(不可妥协):并⼊取数的全球视野数据(M9/M10/M11),在融⼊报告前必须⽆⼀
例外通过完整核验,绝不绕过治理直接进推理。具体说:供应占⽐必带误差带和来源(缺则标"未验证");海
外⽬标价叠⼀道传导折扣,只作⽅向性参考、不⼊锚;受益判断要过实现度闸(要证明真有能⼒、认证、
产能、订单,证不出就降级为"仅当故事看")。并⼊取数不等于放松规则——它不再单列成⼀层,反⽽更
容易被轻处理,所以这⾥的标准和国内数据完全⼀致,不因"是参考视⻆"或"信息来⾃海外"⽽简化。
⼀个现实观察:当 agent 被强制只在已购买的可信数据源⾥检索时,基本就不再编造了。所以治理的重
⼼更多落在另⼀处——外部检索和财报⼝径冲突时怎么裁定:先分等级,有冲突时优先⽤更准的(财报优
先),拿不准的列出来⽽不是默默采信;⽹⻚、访谈类的⾮权威数据,只作"财报⾥没有时的有效补充"。
⼀个常⻅误解要说清:⼝径规整和信源治理这两层不做分析、不做加权、不出结论,它们到"把数据核验⼲
净、标好来源与⼝径"为⽌,真正的分析在⽅法论引擎。污染检测也不是"多源加权":同源洗稿、卖⽅抱团
的⽬标价计为单⼀信源,只降权、不加权。
推理层
M6 ⽅法论引擎:把"⼀份好分析该看哪些维度、必须问哪些反⽅问题"固化成⼀个填空模板,让每份报告都
按同样的⾼标准产出。维度包括业务纯度、壁垒、利润率、客户集中度、产能、单台价值量、技术路线⻛
险、估值位置等。强制反⽅四问:哪部分没被市场定价?空头会盯哪个变量?买的本质是什么?什么变量⼀出
现就证明判断错了?

模式配⼀条测试),并扩为多维评价加机器裁判。
M8 模型路由:按任务难度派不同模型,配合缓存,控成本。
全球视野(M9/M10/M11):并⼊取数层的检索通道
这三块不再单列成⼀层,⽽是取数层⾥⼀条带特定信源和规则的检索通道。内容不变,纪律红线也不变(在治理
层强制):
M9 产业链图谱:⼀张"谁给谁供货、占多少份额"的全球半导体地图。数据多来⾃纪要、报告、公司信息,
经 AI 分析构建;份额多为估算,必带误差带和来源。这种知识图谱的展示效果⼤于实际意义,更适合给 AI ⽤
(强的供货边关系便于严格推理哪些公司相关),给⼈看的可视化反⽽要克制、别太繁复。理想上全流程⼈⼯
复核更好,但⼯作量极⼤,⽽做产品的初衷正是替代⼈⼯,所以以 AI 构建为主、抽样复核;不过 AI 产出的供
应关系和占⽐仍须满⾜信源核验与误差带标注,不因"是 AI 出的"⽽免检。
M10 跨市场对标:把 A 股公司和海外同⾏对应起来。这⾥的"海外⽬标价"要说清:指海外投⾏对海外公司的
⽬标价,⽐如某投⾏把英伟达、CoreWeave 这类海外标的的⽬标价从 200 上调到 300 美⾦(数字为示意),
不是海外投⾏给 A 股的⽬标价。映射、传导到相关 A 股时(⽐如英伟达⽬标价提升、寒武纪可能受益),这
个"受益"结论要过实现度闸,证不出就只当故事看;叠⼀道传导折扣,只作⽅向性参考、绝不当估值锚;映射必
须写清前提条件。
M11 异动监测与传导:盯全球价量异动,顺着产业链图谱传导到相关 A 股(⽐如隔夜美股储能暴涨,提示 A 股
储能);区分"整板块⼀起动"(正常)和"某只股偏偏反着⾛"(罕⻅信号);对"谁受益"强制过实现度闸。
这三块仍带较强的"不⼀定准"的属性,它们提供的是另⼀个视⻆,经治理后融⼊报告,不喧宾夺主。
沉淀层(纵向)
M12 假设台账:把每个判断的⽣命周期(线索、验证、兑现或证伪)存档。它记录的是认知状态,不是仓位,任
何状态都不触发交易。完整流程是这样:分析师把判断、"什么算我错"、复查⽇期填进台账;到期系统⾃动
提醒、拉最新底层数据对照;由⼈确认兑现或证伪;复盘统计反哺下⼀轮,也可以回流到记忆⾥。

1.5 数据源、许可与时效
数据分两类:
1. 接⼝可直接请求的"本地"数据:Wind、iFinD、Choice 和海外研报等⼤多有接⼝,实时请求即得。
2. agent ⽹络检索的数据:⽤关键词在公开⽹络搜(⽐如⾏业⼤佬的演讲、官⽹更新),把接⼝拿不到的重要信
息搜回来、存下。全球视野检索也属于这⼀类(带特定信源和规则)。
许可与时效:
国内数据⾛商业授权(规避诉讼⻛险);⽤量还远没到被限制的地步,真⽕爆了可以再谈。
海外英⽂报告⻛险较低,可以本地缓存,尤其是深度报告(100 多⻚、两三个⽉发⼀次、时效约⼀个⽉),本地
存加建索引更划算。
时效性:实时取数保证拿到最新;研报会随时间冲突(⽐如⽬标价从 300 美⾦更新到 800 美⾦),统⼀⽤最新
的。
可外卖的信源(远期机会,三类):⼀是美光、台积电等海外⻰头的财报与电话会;⼆是⻩仁勋等⾏业⼤佬的关
键发⾔(⽐如⻩仁勋评 CoreWeave,当天该股 208 到 350 美⾦);三是英伟达、台积电官⽹合作伙伴清单的
每⽇快照加⽐对。三类都极可信,但国内缺稳定渠道,若能稳定抓取,本身也可以作为数据产品对外卖。但它
们⼯程量很⼤(要做信源名录和时间表规划、渠道标准化、⽇级监控,体量甚⾄可能超过主系统本身),作为
独⽴⼦项⽬放到后期,不进⾸期主线。
1.6 ⾸期(MVP)范围与构建顺序
⾸期形态:
三类问题全覆盖:单标的、赛道、两标的对⽐。赛道流程和单标的差不多,只是牵涉多家公司;未上市公司可
以靠外部检索补市场占有率等信息,但它⽆法估值、对上市公司股价没有直接影响,所以不强求。
领域:半导体与 AI 资本开⽀链。
报告制:⼀问⼀份结构化报告;⾸期不做交互追问、不做缓存、不做多模态。
实时取数:直接请求接⼝加 agent 检索,不预先全量抓取(抓取范围和周期都不好判定,成本也⾼);缓存留到后
期做体验优化时再上。
全球视野范围:⾸期只⽤已订阅、已有接⼝的信源;可外卖信源(美光财报、⼤佬发⾔、官⽹快照)留到后期,
不进⾸期。
