摘要:五个关键结论
1. 财搭⼦与我们在功能形态上⾼度同构,在产品定位上是两个物种——是分⼯不同,不是⾼下之分。 它的链路(提
问/选题 → 意图分类 → 多智能体协作 → 带溯源标注的研报 → 对话式 Agent)与我们的主链路在流程拓扑上
⼏乎⼀⼀对应;分野在⽣产⽅式(每⽇选题、预⽣成分发 vs 按问现场取证)、质量约束的实现⽅式(统计性幻觉指
标 vs 单条数字级硬阻断)与输出边界(信号推送 vs 不出指令)。两套取舍各⾃适配各⾃的⽤户(海量散户 vs 责
任制机构)。⼀句话:它把研报做成消费品,我们把研报做成证据链。
2. 它的研报做了细致的产品化实现,但实测证明它是"编辑部",不是"引擎"。 深度研报为系统每⽇选题、预⽣成、
单标的(⼀股⼀报、带版本化更新),⽤户不能点题定制;所谓"5 分钟⽣成"的真实经济学是⼀次⽣成、全体分发。
产品化亮点(动态研报、评分分层、评级三⻆)值得借鉴;治理纪律位(⼝径、信源分级、观点隔离)在公开证据层
⾯未⻅成体系呈现(§4.3,标注为推断⽽⾮定论)。
3. 它把评测基准做成了顶会成果并开源(FinS-Pilot,CIKM 2025),这是对我们评测模块最直接可⽤的公开资产。
从真实⽤户⽇志构建、9 类/62 ⼦类意图分类、双查询型双评价体系;其关键实验("⽆检索时全部⼤模型在实时
数值题上准确率为 0")是"实时取数不可省"最硬的公开证据。
4. 它的真实增⻓引擎是微信公众号邀请码分销⽹络与创始⼈个⼈ IP,⽽⾮产品⾃传播。 体量仍⼩:合伙⼈播客⾃
述累计⽤户"将近 20 万"(2026-07)、"商业化逐渐跑通"、"4 ⽉(Agent 模式上线)以来全⾃然流量与商业化数
据变好" 实·⾃述 ;App Store 仅 17 个评分;第三⽅转述"6 个⽉ ARR 数百万" 单源 。2026 年⽀付宝、且慢、
国资系相继⼊场,C 端窗⼝正在收窄——这反⽽验证了机构级 B 端是各⽅都没占的空档。

三、产品实测(项⽬组亲测,2026-07-03)
我们完成了注册实测(微信⼩程序端),核⼼发现如下:
3.1 研报是预⽣成的,不是⽤户点题⽣成
系统"针对当天有价值的内容"每⽇选题、预先写好深度报告,⽤户消费现成品;不⽀持⾃主选择研报的类型或⽅向。
这与三条公开证据互证:解读共享缓存("若已有⽤户⽣成过解读,直接展示精炼结论")、"免费解锁⼀篇历史深度研
报"、动态研报(30 天持续可查)。
含义:所谓"5 分钟⽣成"更接近营销话术,真实经济学是⼀次⽣成、全体分发——它的主链路是"系统选题 → 预⽣成
→ 订阅分发"(编辑部形态),⽽不是"任意问题 → 现场取证 → 报告"(引擎形态)。
3.2 单标的制与研报结构
每份深度研报针对⼀家企业/⼀只股票。实测看到的报告结构为四段:
1. 本次更新的内容及总览——报告带版本化"更新"⼩节,与"动态研报"机制对应;
2. 数据展示及其背后的含义;
3. 深度分析与核⼼结论——会下"业绩增⻓失速是真实存在的"这类明确断⾔;
4. 其他:技术⾯分析(⽀撑位、压⼒位)、今⽇洞察、⻛险拆解。
3.3 ⽣成机制的实测体感
多智能体分⼯可感知:不同维度的智能体(如"情绪调节员"管市场情绪/恐慌指数,"K 线破壁⼈"管技术指标/筹码
结构)各⾃分析后汇编成⼀份研报——与其官⽅智能体档案("宁哥擅⻓ K 线破壁")及"智能体辩论"宣传互证。
Agent 本质:类似蚂蚁系通⽤助理——通⽤ Agent 注⼊⾦融内容与 skills(技能包) 后获得领域表现;与公开证据
链(外部基座路由 + ⼈设 prompt + 专属⼯具/数据集 + skill 体系,⻅ §六)⼀致。
整体判断:它是⽤ AI 对现有的⼤量数据做整理,再⽤多智能体从多⻆度(含对抗式)整合成品。
⾃选股、模拟盘等常规功能存在,但⾮产品主线,不构成分析重点。
3.4 第三⽅可⻅的界⾯与输出佐证
来⾃⼩红书⽤户转贴的产品截图与输出样例 实 :
个股深度报告界⾯:⼤发分(如 59.43)+ PE-TTM(如 12.46 倍)+ ⼀句话逻辑("PE/PS 历史极低位")+ "⼤发帮你
整理了 9 条历史⾼相似资产的规律";"发现个股"筛选器含低估值/⾼热度/好研报等因⼦;
输出⽂本样例(市场宽度分析):"上涨个股从周⼀的 4005 只锐减⾄昨天的 1271 只""封板率降⾄ 46%""融资买
⼊占⽐ 10.42%,接近去年'924'⾏情时的峰值"——数据密度确实⾼;
同⼀样例也有两处值得注意的问题:直接引⽤"淘股吧的观点"作为论据(散户论坛观点进⼊分析层);存在模板缺
字的⽣成瑕疵("符合中提到的'⾏情扩散成⻓活跃'特征")。

9.1 结论:像不像?
在功能形态图上⾼度相似;在产品本质上是两个物种。
形态同构(先承认"像"):它的主链路"选题/提问 → 意图分类 → 多智能体并⾏(专属数据+⼯具)→ 辩论综合 → 带数
据源与时间标注的研报 → 对话式 Agent",与我们"query → 编排器拆解 → 多通道取数 → ⽅法论框架分析 → 带溯
源报告"在流程拓扑上⼏乎⼀⼀对应;它先做"⾃动输出研报"再升级"对话式 Agent"的节奏,也与我们"报告制起步、
交互追问后置"的规划同构。
本质分野(按证据强度排序):
1. 纪律哲学:⼋个硬校验位对照(§4.3)——覆盖约 1.5 个,⼀个⽅向相反。它把可信度做成统计指标与观感(幻觉
率、来源⻆标、评级三⻆),我们把可信度做成结构约束(缺⼝径即作废、⽆来源即阻断、观点结构上进不了事实
层)。
2. 商业形态:编辑部 vs 引擎。它每⽇选题、预⽣成单标的研报、订阅分发,⽤户不能点题;我们按分析师的任意问
题现场取证出报告。这不是交互取舍,⽽是⽣意分野(内容分发 vs 研究基建),它也解释了"5 分钟"的成本结构。
3. 数据加⼯深度:双⽅可能都拿得到优质数据库(它的⽣产库授权未公开,不宜假定更弱,⻅ §6.3);可确认的差异在
加⼯环节——财报 PDF 原⽂解析、⼝径规整、纪要治理,其公开材料未⻅对应痕迹,⽽这恰是我们⼯作量的⼤
头。差异在"对数据做什么",不在"买了什么数据"。
4. 输出边界:它的终点是"该买该抛⼀⽬了然"+ 信号推送(踩监管边缘);我们的终点是"证据⻬、反⽅问过、决策留
给⼈"。
5. 深度档位:预⽣成的通俗研报服务"看不过来"的散户;我们⼗⼏分钟不漏线索、每个数字可反查,服务"要对结论负
责"的私募。
⼀句话:同⼀批技术积⽊,搭了两个物种——它把研报做成消费品(可读、可信感、可分享),我们把研报做成证据链(可
查、可证伪、可追责)。 它证明了这套流程拓扑⼯程上可⾏、散户市场买账;机构级纪律引擎这⼀档,⽬前未⻅有⼈交
付——对我们⽽⾔是空档,同时也是⼀个仍待市场验证的假设。
补充两点公允校准:其⼀,"编辑部"形态更可能是成本、质控与合规约束下的分发选择,⽽⾮能⼒缺失(§4.5)。其⼆,合
伙⼈⾃述"我们做所有产品功能的第⼀要素是可信,其他都是添砖加瓦"——价值观与我们⾼度同源;分野不在初⼼,在
实现⽅式(统计性治理 + 算法框架 vs 单条数字级结构约束)与验收对象(散户的体感信任 vs 机构的审计信任)。两条
路线各⾃成⽴,服务不同市场。

6. 合规姿态是差异项:它靠免责声明控制责任(信号化路线的监管敞⼝在放⼤),我们把合规内置进流程(MNPI 复
核、不出指令)。两条路线各⾃适配各⾃的市场;对持牌机构⽽⾔,后者是更可采购的形态,且在监管收紧情境下
差异会放⼤。
7. 窄域纵深 vs 全市场浅覆盖:它覆盖全 A 股 + 1200 只 ETF,必然浅;我们锁半导体与 AI 资本开⽀链,配产业链图
谱、跨市场对标、异动传导(全部过治理),能回答它结构上答不了的问题。
8. 它教育了市场,我们承接下⼀问:"AI 能出研报"的认知已被它和巨头们建⽴;下⼀问必然是"AI 研报错了怎么办/凭
什么信"——那正是治理层的问题,是我们的开场⽩。
