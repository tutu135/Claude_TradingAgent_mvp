# 单股票投研 Demo —— 一页纸摘要

> 给先读材料的人。三分钟读完，带着问题来聊。

## 一句话

用一份**冻结的**真实公开资料（中芯国际 20 份年报/季报/电话会纪要），跑通一条从原始 PDF 到研究报告的完整流水线，验证一件事：**报告里的每一个数字，能不能都追溯回原文的确切位置。**

成功标准**不是**预测准不准，而是**报告准确、全面、可核验**。

## 为什么这不是"把年报丢给 GPT"

大模型能写出流畅的研报，问题是你无法逐个核验里面的数字——真数字和幻觉数字混在一起，长得一模一样。

这个项目的做法是把"可核验"变成**工程约束**：

- 每个数字都必须能沿 `evidence_id → fact_id → chunk_id → material_id` 点回原文的页码和章节
- 做不到这一点的句子，**整句从报告里删掉**
- 最后有一道门禁，回读渲染完的报告，断言自由叙述区里的数字数量为 **0**

代价很直白：主维度 D1 的结论叙述被删得只剩 **19%** 的字。项目选择接受——**难看但可核验 > 好看但不可核验**。

## 流水线（七个阶段）

```
20 份公开材料（冻结 + 哈希）
  → 3,399 个结构化片段（BM25 检索，不用向量）
  → 20,114 条原子事实（Decimal 保精度，单位/期间/口径全部拆开存）
  → 20,114 条治理证据（信源分级 T1-T4 / 同源去重 / 三档可用性）
  → D1-D7 七个维度的结论 + 证据分（脚本反算，模型不给分）
  → 反方质询（最多两轮，实测翻转了 2 个维度的结论）
  → report.md（十章节，数字只出现在证据表里）
```

跑一次 1 分 45 秒。8 个 CLI 约 9,700 行，测试约 7,000 行 / 144 个用例。

## 三个可能有意思的设计决定

**1. 材料不会自动变成证据。**
进快照的材料统一标 `ACQUIRED_UNASSESSED`——"已取得，未评估"。采集只管"有没有出处、时间对不对、字节能不能哈希复现"，**完全不判断真假**。能不能拿来支撑结论是后面独立一层的事。这样"我找到了这份资料"和"这份资料可信"就不会被偷偷合并。

**2. 模型判断被夹在两层确定性逻辑中间。**
选证据是确定性脚本（按检索分数和来源多样性挑，有预算上限）；模型只在中间做一次有界判断，且**只能引用给定候选集里的 ID**，引用集外的直接判失败；证据分由脚本从模型选中的证据**反算**，模型不产出分数。实测首轮有 3/7 个维度因为"因果措辞没有标注来源"被拒绝重来。

**3. 端到端不重新调模型（这条最容易被质疑）。**
模型的判断产物被冻结成只读输入，跑流程时零模型调用。所以"端到端可复现"证明的是**从冻结输入到最终产物的确定性重放**，不是判断层被重新执行。<br>
这么选的原因是实测的：每个维度只有两次生成机会，第二次再失败就强制 UNKNOWN。真调模型会让同一份验收**一次通过一次失败**——不可复现的验收不是验收。判断层本身的可信度由 12 项校验加全过程留痕承担。<br>
代价已如实记录在架构决策文档里。

## 跑出来的真实结果

| 项 | 实测 |
|---|---|
| 七个维度结论 | 5 个 MIXED + 2 个 UNKNOWN，**无一 SUPPORTED** |
| 反方质询 | 5 条，翻转 2 个维度（D2 支持→混合、D7 混合→未知） |
| 散文里的数字 | 检出 442 个，整句删除 126 句，**泄漏 0** |
| 冲突组 / 隔离证据 | **0 / 0** |
| 政府补助敏感性 | **0 条** |
| 调节公式复算 | 7 条：4 条算对，3 条因口径不匹配无法计算 |
| 缺口登记 | 4,922 条 |

**这些 0 和 WARN 不是 bug，是数据的真实承载力。** 项目的硬线是：机制由合成测试证明存在，真实运行的零值原样写进报告并说明原因，**绝不为了让报告好看去造数据**。

同理，七个维度没有一个 SUPPORTED——如果它跑出一个漂亮的"证据充分支持可持续改善"，那才该怀疑。

## 已知的最大问题（没修，但已披露）

**事实抽取的语义正确性没有门禁。** 真实案例：

```
原文    息税折旧摊销前利润率（%） 53.8 52.4 增加1.4个百分点
抽成    折旧费用 = 1400 元
状态    规整通过 → T1 / 可用 / 可承重
```

指标认错、单位认错（百分点当成钱），却一路绿灯。粗筛估计 4,575 条数值里约 179 条（3.9%）有类似问题。

根因是：三档证据状态的六条判定**全部在判元数据健不健全**（时间、定位、准则、单位、信源、冲突），**没有一条在判抽取的语义对不对**——整条链上没有任何一关比对过「值」和「原文」。

这是设计缺口，不是实现 bug。已写进报告第九章"数据限制"，修复方案分三档估过工作量，尚未动手。

## 明确不做的

不是产品，是个人 / 非商业 / 本地 / 不可发布的一次性 Demo。不输出买卖建议、目标价、估值锚、仓位建议、投资评级、系统预测（这些是硬门禁，报告生成后会扫词表）。不建通用架构：无 DAG、队列、调度器、数据库、插件系统、规则 DSL。
