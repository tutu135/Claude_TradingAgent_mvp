# 问答手册

**给谁看**：你自己，汇报前过一遍。

**怎么用**：每个问题分四块——「一句话答」是可以直接说出口的；「被追问再说」是第二层；「现场打开」是可以当场展示的文件；「⚠️」是容易翻车的地方。

**前提**：师兄懂 AI / 工程，不懂金融。所以涉及会计的地方要主动解释，涉及 RAG 的地方可以直接说术语。

# 🔴 第一组：三个真正危险的问题

答不好这三个，整场汇报的可信度会塌。建议**把这三个答案念熟**。

## Q1. "这跟我直接把年报丢给 GPT 让它写研报，有什么区别？"

**必问。而且是善意的问题——他想知道你多做的这些工作值不值。**

### 一句话答

> GPT 会给你一段流畅的文字，里面真数字和幻觉数字长得一模一样，你没法逐个核验。这个项目把"可核验"做成了工程约束：每个数字都能点回原文的页码和章节，做不到的句子会被整句删掉。

### 被追问再说

三个具体机制：

1. **溯源链**：每个数字带 `evidence_id → fact_id → chunk_id → material_id`，能一路点回"哪份材料、第几页、哪一章"。
2. **整句排除**：模型写的叙述里，凡是带了数字但那个数字没有对应证据行的**整句删除**——不是把数字抹掉。因为抹字符会留下"毛利率由上升到，改善个百分点"这种垃圾，看起来还像句人话。
3. **最终门禁**：报告渲染完之后，程序**回读这个文件**，扫自由叙述区，断言未绑定数字数量为 0。

代价说清楚：**D1 维度的结论叙述被删得只剩 19% 的字**。这是有意接受的——难看但可核验，好过好看但不可核验。

### 现场打开

`single-stock-demo-run/report.md`，翻到第三章 D1。让他看两样东西：上面被掏空的叙述，和下面那张 16 列的证据表。对比最有说服力。

### ⚠️ 不要说

不要说"GPT 会胡说八道所以我不用它"——**这个项目里模型是核心组件之一**（D1–D7 的判断就是模型做的）。准确的说法是"模型做判断，但判断被夹在两层确定性逻辑中间，而且只能引用给定的证据 ID"。

## Q2. "你说冻结重放，那模型判断层在端到端里从来没真跑过——这验收算数吗？"

**这问题很内行。如果他问出来，说明他真的看懂了。项目文档里白纸黑字承认了这个代价，所以你可以坦然答。**

### 一句话答

> 算数，但证明的对象要说清楚：端到端证明的是**从冻结输入到最终产物的确定性重放**，不是判断层被重新执行。判断层的可信度由另一套机制承担。

### 被追问再说

**为什么这么选**——理由是实测的，不是偷懒：

- 每个维度只有**两次**生成机会，第二次再失败就强制 `UNKNOWN` + 证据分 0 + 整个阶段 FAIL。
- 实测首轮就有 **3/7 个维度被拒绝**（D1、D2、D3，全是同一个原因：用了"因而"这个因果连接词但没标注来源）。
- 所以真调模型会让**同一份验收一次通过、一次失败**。不可复现的验收不是验收。

**那判断层靠什么保证？** 12 项具名校验 + 全过程留痕。每次模型输出都被逐项检查（引用的 ID 在不在候选集里、有没有禁止词、因果措辞有没有标注来源、分数和状态绑定对不对……），不合格的直接拒绝重来，所有尝试——包括被拒绝的——全文留在 `analysis-attempts.jsonl` 里。

### 现场打开

`frozen-analysis-inputs/analysis-attempts.jsonl` —— 10 条记录，前 6 条是 D1/D2/D3 各拒一次再通过，错误码都是 `UNATTRIBUTED_CAUSAL_CLAIM:finding_statement:因而`。**这是最好的演示**：闸门真的拦下过东西，而且同一个词拦了三次。

### ⚠️ 不要说

不要说"因为调模型太贵了"。真实理由是可复现性，不是成本。也不要假装端到端跑了模型——文档里承认了，你也承认，这反而加分。

## Q3. "3.9% 的事实抽错率，那你的结论不就建立在错数据上？"

**这是项目最大的真实缺陷。策略：承认得比他更狠，然后展示你知道根因在哪。**

### 一句话答

> 是的，这是已知未修的缺陷，已经写进报告第九章披露了。根因比错误率本身更值得说：**整条链上没有任何一关比对过「抽出来的值」和「原文」。**

### 被追问再说

先给例子（**这个例子很有冲击力，建议现场展示**）：

```
原文    息税折旧摊销前利润率（%） 53.8 52.4 增加1.4个百分点
抽成    metric_id = 折旧费用，单位 = 钱，1.4 × 1000 = 1400 元
状态    规整通过 → T1 / 已披露事实 / 可用 / 可承重
```

指标认错（中文别名"折旧"匹配到了"息税**折旧**摊销前利润率"内部）、单位认错（"个百分点"没被识别，退回到表格级默认单位"千元"）。

**为什么没拦住**：三档证据状态的六条判定条件，全部在判**元数据健不健全**——时间对不对、定位解析得出来吗、会计准则清楚吗、单位期间全吗、信源什么等级、有没有冲突。**没有一条在判抽取的语义对不对。**

这是**设计缺口，不是实现 bug**。修法已经估过工作量，三档：

| 方案 | 成本 | 效果 |
|---|---|---|
| 加交叉校验门禁（单位是钱但原文含"百分点"→ 判矛盾降级） | 约 1 天 | 治标，能一次拦住这 179 条 |
| 修抽取层（中文别名加词边界 + 正则补"个百分点"） | 2–3 天 | 治本一半，但要重跑 03/04 |
| LLM 抽取 + 构建期冻结 | 1 周+ | 换地基 |

而且还有个**前置问题没验**：PDF 表格的单元格结构可能在**解析阶段**就被压平成一根字符串了。如果是这样，前两个方案都是在坏地基上盖房子。这是下一步要先验的东西。

### 现场打开

`DEMO-KNOWN-ISSUES.md` 的 A1 和 B2 两节。**主动打开自己的问题清单，比被问出来强得多。**

### ⚠️ 不要说

不要辩护"3.9% 不高"。也不要说"这只是启发式估计所以可能没那么严重"——文档里写的是"启发式粗筛，未人工核对"，你就照这个说，**不确定性本身要如实传达**。

## Q4. "七个维度全是 MIXED 和 UNKNOWN，那这系统证明了什么？"

### 一句话答

> 证明了它不会为了给你一个漂亮答案而编。成功标准从一开始就不是"给出强结论"，而是"报告可核验"。

### 被追问再说

而且从投研角度看，MIXED / UNKNOWN **恰恰是诚实的**：现有 20 份材料确实不足以支持"已进入可持续改善阶段"这个判断。具体到维度：

- **D2（利用率驱动）**：快照里**一条可用的产能利用率数值都没有**，所以承重指标白名单是空的。
- **D5（行业周期）**：候选证据里没有任何可承重数值，只有文字。
- **D7（可持续性）**：唯一正当的承重指标是经营现金流，快照里有 6 条可用记录，但**没有一条被 D7 的检索查询族命中**——这是检索层的缺口，已登记 gap。

项目选择把这些**如实写出来**，而不是拿一个相关的数字凑上去假装有证据。

**反过来说**：如果它跑出一个"证据充分支持可持续改善"，那才该怀疑数据是不是被凑出来的。

---

## Q5. "冲突 0、隔离 0，那你的治理机制到底跑起来了没有？"

### 一句话答

> 真实数据上没有观察对象，机制由合成测试证明存在，报告里把零值和原因原样写出来。这是有意的：绝不为了让报告好看去造数据。

### 被追问再说

- **隔离为 0**：三条隔离规则（材料超出 `as_of`、内容定位解析不出、规整被阻断）一条都没触发。两种解读目前无法区分——可能是采集阶段确实把不合格材料挡在门外了（好事），也可能是机制从未被真实检验（风险）。**文档里两种都写了。**
- **冲突为 0**：冲突检测被有意限制在人工核验过的白名单上，目前白名单只有 2 条用户确认的事实。这是"Demo 简约"的取舍，代价就是这个能力展示不出来。

机制本身有测试覆盖：合成一条被隔离的证据，断言它**不会进入任何维度的证据表**，同时**必须出现在报告第九章**。

### 现场打开

`tests/test_generate_research_report_cli.py` 里的 `QuarantineAndConflictFixtureTests`。

## Q6. "为什么只用 BM25 不用向量检索？现在不都上 embedding 了吗？"

### 一句话答

> 有一条写死的实验准入规则：BM25 效果是 PASS 的时候不做实验。实测就是 PASS，所以没做。

### 被追问再说

规则细节（这条规则是**提前写死的**，不是事后找的理由）：

- BM25 = **FAIL** → 先修分块、查询、词表、定位，不许拿 embedding 打补丁
- BM25 = **WARN** 且**预先登记**了具体的词法漏召回 → 允许在同一个集合上做一次对比实验
- BM25 = **PASS** → 不做实验

实验结果也分三档：`ADOPTED`（WARN 转 PASS 且硬指标不退化，才能进 Demo）、`IMPROVED_NOT_ADOPTED`（有改善但整体仍 WARN，只存实验记录）、`REJECTED`。

**为什么这么设计**：向量检索会引入一个不可复现、不可解释的相似度分数。这个项目的核心卖点是可追溯，多加一个黑盒要有实打实的收益才划算。

另外一个更重要的点：**分块策略比检索算法更关键**。项目不用固定长度滑窗，改用"结构原子"——表格片段必须**连表头、单位、期间、脚注一起保留**。因为一张表被从中间切断，那些数字就再也不知道自己的单位了。

## Q7. "模型幻觉怎么防的？"

**AI 背景的人最关心这个。**

### 一句话答

> 三层：模型只能从一个封闭的候选集里选证据；引用集外的 ID 直接判失败；分数不由模型给，由脚本从它选中的证据反算。

### 被追问再说

按顺序讲：

1. **候选集是封闭的**。选证据是确定性脚本做的——按检索分数和来源多样性挑，每个维度先播种 3 个独立来源组，再按分数填到 6 万字符预算或 64 个片段为止。模型拿到的 prompt 由脚本从这个集合**确定性拼装**，不是人手写的。
2. **引用合法性是硬闸**。模型输出的每个 `evidence_id` 都要在本维度候选集里，且状态必须是 `USABLE`。引用集外的 → 整次输出作废重来。
3. **分数是反算的**。模型只说"我选了这几条证据、方向是什么"，证据分由脚本数独立来源组、看有没有可比的跨期数值来算。**模型碰不到分数**。
4. **因果措辞要标注来源**。句子里出现"导致/推动/因此/因而"这类词，同一句必须有"公司称/年报披露"这类来源标注，否则判失败。**实测这一条拦下了 3 次输出。**
5. **禁止输出词表**是最后一道，扫到"买入/目标价/估值有吸引力"之类直接失败。

### 现场打开

同 Q2，`analysis-attempts.jsonl`。10 次尝试 3 次被拒，全是第 4 条规则。

## Q8. "`governance_status` 为什么是 WARN 不是 PASS？"

### 一句话答

> WARN 不是失败，是"硬条件都过了但有未解决项"。而且它只由三个阶段合成，不是全流程总评。

### 被追问再说

- `governance_status` = 检索 / 规整 / 证据治理三者取最坏值 = PASS / WARN / WARN → **WARN**。
- **分析和质询的状态不并入**，在报告里并列展示。因为治理和分析在需求里是两条不同的概念轴，造一个跨轴总状态会同时丢信息和混淆语义。
- WARN 的来源：规整阶段有记录是 `PARTIAL`（部分字段 UNKNOWN），证据治理阶段有未解决 gap。

## Q9. "证据分怎么算的？为什么不给个总分？"

### 一句话答

> 0–3 四档，由脚本从模型选中的证据反算。没有总分，而且这是硬性禁止的。

### 被追问再说

分档规则：

| 分 | 条件 |
|---|---|
| 0 | 没有承重证据（**强制**结论为 UNKNOWN） |
| 1 | 单一来源组、单一期间，或只有一个数据点 |
| 2 | 两个以上独立来源组，或有可比的跨期数值 |
| 3 | 承重指标上的可比跨期数值 + 两个以上独立来源组 + 承重证据无未决冲突 |

注意**分 0 强制 UNKNOWN，但反过来不成立**——证据分 2 也可以是 UNKNOWN，因为证据存在但方向互相矛盾。

**为什么没总分**：把七个维度加权成一个数，等于偷偷做了一次投资评级，而投资评级是这个项目明令禁止的输出。所以 `overall_score` 是脚本写死的常量 `NOT_APPLICABLE`。

# 🟢 第三组：好答的

---

## Q10. "多大规模？做了多久？"

8 个命令行工具约 **9,700 行**，测试约 **7,000 行 / 144 个用例**，5 份规则文件，5 个架构决策文档。跑一次完整流程 **1 分 45 秒**。

分成 6 张票做，每张票的节奏是：先把规划往死里质询（grill）→ 冻结规划写进 ticket → **换一个新窗口**实现。规划和实现不在同一个窗口里做。

## Q11. "怎么测的？"

每个阶段一个 CLI 一份测试，全部是**端到端跑真命令**（子进程调 CLI，不 mock 内部函数）。真实数据里没出现的情况用合成 fixture 覆盖——比如隔离证据、冲突降级、政府补助敏感性、治理 FAIL。

另外有几个**结构性测试**比较有意思，比如断言"编排脚本的源码里不出现 `subprocess`、不 import 任何阶段脚本"——把架构约束写成测试。

## Q12. "能推广到多只股票吗？"

**明确不能，而且是有意的。** 这是一次性 Demo，规则表、指标映射、查询族、同业名单全部是针对中芯国际写死的。项目的硬约束里写着：不建通用架构，不为假设的未来需求加抽象。

要做多只股票，得重做规则层——但流水线的**形状**（材料→片段→事实→证据→发现，每步都要过关）是可复用的思路。

## Q13. "为什么不用 LangChain / LlamaIndex 之类的框架？"

约束里写死了：不建 DAG、队列、调度器、数据库、插件系统、规则 DSL。七个阶段的顺序是**写在 Skill 的 Markdown 文档里的文本常量**，不是可配置的工作流。

理由是：一旦顺序进了脚本的控制流，哪怕现在只有七步固定，它已经是个步骤执行器了。连脚本名字都是防线——叫 `validate_demo_run.py`（校验），不叫 `orchestrate_*`（编排），因为后者会持续邀请后来的人往里加东西。

## Q14. "数据从哪来？合规吗？"

20 份公开材料：港交所披露、巨潮资讯（A 股）、半导体行业协会、公开电话会纪要页面。13 个 PDF + 7 个网页，全部发布时间 ≤ `as_of`（2026-05-15）。

用途声明写在案例文件里：个人 / 非商业 / 本地 / 禁止再分发 / 禁止用于模型训练。每份材料记录了来源入口、发布主体、发布时间依据、条款链接和已知限制。

## Q15. "下一步做什么？"

**先验一件事，它的结论决定其他所有事怎么修**：打开解析后的 JSON，看 PDF 表格的单元格结构是不是在解析阶段就被压平成一根字符串了。

- 如果结构还在 → 是分块阶段丢的，修分块
- 如果解析阶段就丢了 → 是更早的欠债，抽取错误率的三个修法都要重新评估

之后才是 Q3 里那三档修法的选择。
