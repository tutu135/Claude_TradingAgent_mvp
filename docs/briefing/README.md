# 汇报材料

给师兄汇报本项目用。六份材料，各有各的读者。

| 文件 | 给谁 | 什么时候用 |
|---|---|---|
| [**00-给师兄的项目报告.md**](00-给师兄的项目报告.md) | **师兄（主材料）** | 最完整的书面材料，25 分钟读完。开头有结构说明，术语都带解释，每节末尾有注释，结尾有五个请教问题 |
| [01-一页纸摘要.md](01-一页纸摘要.md) | **师兄（速览版）** | 只有三分钟时用这份；有时间就直接给 00 |
| [02-术语速查.md](02-术语速查.md) | **你自己** | 名词不懂时查，比 00 里的注释更全 |
| [03-问答手册.md](03-问答手册.md) | **你自己** | 汇报前过一遍，红色那三个问题念熟 |
| [04-报告导读.md](04-报告导读.md) | **你自己 + 现场展示** | 逐条读懂那份正式报告；证据卡片可以直接点开原文 PDF |
| [05-流程可视化.html](05-流程可视化.html) | **师兄 + 现场展示** | 汇报主线。浏览器直接打开，单文件、离线、可发走 |

**你自己的准备顺序**：00（先把故事读顺）→ 02（补名词）→ 03（准备答案）→ 04（要现场展示时才细看）。

**给师兄的**：直接发 00，它是自包含的，不需要配合别的文件读。当面聊就配合 05 展示。

> ⚠️ 另有一份 `docs/mentor-project-report.md`（别的窗口写的，内容准确但术语密度高，且未入库）。
> 它和 00 讲的是同一件事，**两份只该留一份**，否则以后改一处忘另一处。00 已经吸收了它最好的一节
> （结尾的「请教导师的问题」）。建议删掉那份，或者明确它是给不同读者的。

### 关于 05

汇报时的主线材料。七个阶段各一页，每页固定回答「这一步拦住了什么」；另有两页贯穿式追踪——
一条真数字（毛利率 20.1%）和一条抽错的记录（EBITDA 利润率 → 折旧 1400 元）各自走完整条链。

它是**手写的静态文件**，不由脚本生成。数字取自 main `0facd28` 的运行产物，重跑流程后如果关键数字变了，
直接改这个文件即可（按「Demo 简约」原则，不为它建生成器）。它和 04 一样**只改呈现方式，不新增任何结论、数值或来源**。

⚠️ 冻结 Spec 规定 Demo **不生成 PDF、网页、Dashboard、API 等外部分发格式**（`spec.md:449`），
该约束针对的是流水线产出的**研究报告**——`generate_research_report.py` 仍然只产出 `report.md`，
其 `prohibited_external_artifacts` 四项照旧全部 `NOT_GENERATED`。05 是**汇报辅助材料**，
不在流水线内、不是 `report.md` 的分发形态，并沿用同样的 `INTERNAL_DEMO_ONLY` / `PENDING_HUMAN_REVIEW` 标注。
它引用了报告里的结论和数字，**不要对外分发**。

### 关于 04

它由 `python scripts/make_readable_report.py` 从运行产物重新排版生成，**只改呈现方式，不新增任何结论、数值或来源**。改完报告或重跑流程后重新执行一次即可。

它做了三件事：把 16 列的证据表拆成带链接的卡片（可直接跳到原始 PDF 的对应页）、把被闸门删掉的句子单独列出来让你看清机制、给每个维度配了中文小标题。

**它没做、也不该做的事**：把数字塞回叙述里。模型从来没说过哪个数字对应哪条证据，硬配对就是伪造溯源关系。

## 聊天时的节奏建议

场景是随性聊 + 现场开电脑看代码。**别一上来就开代码**，按这个顺序：

1. **先开报告** `single-stock-demo-run/report.md`，翻到第三章 D1。
   让他看见两样东西：上面被掏空的叙述（只剩 19% 的字），下面那张 16 列的证据表。
   这一眼就能引出"为什么搞成这样"，你顺势讲可核验性这条主线。

2. **再开尝试日志** `frozen-analysis-inputs/analysis-attempts.jsonl`。
   10 次模型输出，3 次被拒，全是同一个原因：用了"因而"但没标注来源。
   **这是最好的演示**——证明闸门真的在拦东西，不是摆设。

3. **然后开规则** `rules/analysis.yaml`。
   让他看承重指标白名单：D2、D5、D7 是空的，D3 只有一条，旁边写着为什么空。
   讲"数据撑不起结论时如实说出来"这条立场。

4. **最后开自己的问题清单** `DEMO-KNOWN-ISSUES.md`。
   主动讲抽取语义错误那 3.9%。**自己先说，比被问出来强得多。**

## 需要更深入时，怎么开新窗口问 AI

这个项目有 20 万字文档和 9,700 行代码，**一个窗口装不下**，硬塞会让 AI 什么都答得浅。按话题分窗口，每个窗口开场都用同一句：

```
读 docs/PROJECT-GUIDE.md，然后回答我：<具体问题>
```

`docs/PROJECT-GUIDE.md` 是为这个用途设计的导览，带实测结果表——所以"结论是什么""冲突几条""泄漏几个数字"这类问题不用再读别的文件。

推荐的窗口题目（**从难到易**，第一个决定整场汇报的框架）：

| 窗口 | 开场白 |
|---|---|
| 1 | `读 docs/PROJECT-GUIDE.md 和 docs/briefing/03-问答手册.md。假设我师兄质疑这个项目的价值，帮我把最尖锐的问题和答案再深挖一层，尤其是他懂 AI 但不懂金融这一点。` |
| 2 | `读 docs/PROJECT-GUIDE.md。把 03 事实规整这一步用人话讲一遍——会计口径、单位期间、IFRS-CAS 桥接分别在解决什么问题，我要能对着白板说清楚。` |
| 3 | `读 docs/PROJECT-GUIDE.md。带我读一遍 single-stock-demo-run/report.md，告诉我每一章在证明什么，哪几章最值得现场展示。` |
| 4 | `读 docs/PROJECT-GUIDE.md 和 docs/briefing/。帮我做一份 15 分钟汇报的大纲，每页放什么图表和数字。` |
| 5 | `读 docs/PROJECT-GUIDE.md 和 DEMO-KNOWN-ISSUES.md。帮我评估：如果要修抽取语义错误，三档方案分别要动哪些文件、风险在哪。` |

**分窗口原则**：换话题就换窗口；同一话题深挖就 `/compact` 继续；要动手写代码一定换窗口。

## 一个提醒

这三份材料是**汇报辅助**，不是项目的权威定义。它们为了好懂做了简化。

真正的权威是 `CONTEXT.md`（术语）、`.scratch/single-stock-demo/spec.md`（需求）、`contracts/contract-map.md`（文件契约）、`rules/*.yaml`（规则）。
被问到细节而你不确定时，**当场打开权威文件查**比凭印象答要好——这个项目本身讲的就是这件事。
