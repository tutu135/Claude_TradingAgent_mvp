框架总览把「可核验」做成工程约束

用一份冻结的真实公开资料——中芯国际 20 份年报 / 季报 / 电话会纪要——跑通一条从原始 PDF 到研究报告的完整流水线，验证一件事：报告里的每一个数字，能不能都追溯回原文的确切位置。

为什么这不是「把年报丢给 GPT」

大模型能写出流畅的研报，问题是你无法逐个核验里面的数字——真数字和幻觉数字长得一模一样。 这个项目的做法不是「让模型少犯错」，而是把可核验性变成结构上无法绕过的约束：

三个机制

  • 溯源链：每个数字都带 evidence_id → fact_id → chunk_id → material_id， 能一路点回「哪份材料、第几页、哪一章」。
  • 整句排除：模型写的叙述里，凡是带了数字但那个数字没有对应证据行的，整句删除—— 不是把数字抹掉。抹字符会留下「毛利率由上升到，改善个百分点」这种看起来还像人话的垃圾。
  • 最终门禁：报告渲染完之后，程序回读这个文件，扫自由叙述区，断言未绑定数字数量为 0。

代价很直白，也已经量化在上面那张卡片里。项目的立场是难看但可核验 > 好看但不可核验。

三个可能有意思的设计决定

1 · 材料不会自动变成证据

进快照的材料统一标 ACQUIRED_UNASSESSED。采集只管「有没有出处、时间对不对、 字节能不能哈希复现」，完全不判断真假。能不能拿来支撑结论是后面独立一层的事。 这样「我找到了这份资料」和「这份资料可信」就不会被偷偷合并。

2 · 模型判断被夹在两层确定性逻辑中间

选证据是确定性脚本（按检索分数和来源多样性挑，有预算上限）；模型只在中间做一次有界判断， 且只能引用给定候选集里的 ID，引用集外的直接判失败；证据分由脚本从模型选中的证据反算， 模型不产出分数。实测首轮有 3/7 个维度因为「因果措辞没有标注来源」被拒绝重来。

3 · 端到端不重新调模型（这条最容易被质疑）

模型的判断产物被冻结成只读输入，跑流程时零模型调用。所以「端到端可复现」证明的是 从冻结输入到最终产物的确定性重放，不是判断层被重新执行。

这么选的原因是实测的：每个维度只有两次生成机会，第二次再失败就强制 UNKNOWN。真调模型会让 同一份验收一次通过一次失败——不可复现的验收不是验收。判断层本身的可信度由 12 项校验 加全过程留痕承担。代价已如实记录在 docs/adr/0005。

深入：为什么是 BM25 而不是向量检索

关键词 / BM25 是必需基线，Embedding 只是可选实验，而且触发条件写死了：只有在 BM25 为 WARN 且实验前已登记具体词法漏召回时，才允许做一次同集对比。BM25 为 PASS 时不做实验； BM25 为 FAIL 时先去修分块、查询、词表或定位，而不是换检索方式掩盖问题。

本次 BM25 直接 PASS，所以向量检索一次都没跑。这不是「向量不好」， 而是这个语料的特点——财报里的指标名是高度术语化的固定写法，词法匹配本来就强； 真正的难点在切分和定位，不在语义相似。

分词器固定保留的领域符号

截断规则

这一步拦住了什么

  • 浮点数——可解析值一律用十进制定点字符串 + Decimal 计算，不得使用 JSON/二进制浮点数。 百分比以原显示数值配 unit=PERCENT 保存，不静默改为小数比率； 百分点用 unit=PERCENTAGE_POINT。
  • 把空白当零——每个数值必须有 value_status： PRESENT / EXPLICIT_ZERO / NOT_APPLICABLE / NOT_REPORTED / UNPARSEABLE / UNKNOWN。 只有原文明确为零、或表格图例明确说明破折号代表零且该图例可定位时才能用 EXPLICIT_ZERO。 空白、破折号、N/A 不得自动转为零。
  • 模糊匹配指标名——指标和主体只通过固定版本映射表规范化。 禁止字符串相似度、词干推断、停用词删除、Embedding 或模型语义归并。 没命中已确认别名就是 UNMAPPED，不猜。
  • 「映射成功 = 可比」——可比性必须绑定明确的比较对象，单独存 comparability_status 和固定原因码。不得保存没有比较对象的笼统可比状态。
  • 运行时自由公式——系统派生只允许固定白名单的 9 个公式，每项实现为固定函数 + 规则 ID。 不建设公式 DSL，不接受运行时自由公式。
  • 晶圆口径互换——8 寸 / 12 寸 / 8 寸等效不是单位缩放。 除非原文明确给了换算规则，否则禁止互换。利用率只保存来源披露值，不用产能与出货反推。

深入：IFRS / CAS 桥接与政府补助敏感性

桥接只实现一个方向

CAS_TO_IFRS，公式固定为 IFRS_TARGET = CAS_BASE + sum(normalized_signed_amount of ADJUSTMENT_DETAIL)。 不接受运行时反向复算。每行标 row_role=BASE|ADJUSTMENT_DETAIL|SUBTOTAL|TARGET， 只有 ADJUSTMENT_DETAIL 进入求和——防止明细、小计和总计重复计入。

复算差异恰为零 → PASS；非零但在容差内 → ROUNDING_DIFFERENCE；超出容差 → FORMULA_MISMATCH。 容差固定为 0.5 × (各行 rounding_increment 之和)，不猜容差： 若任一必要披露精度缺失，则只有差异恰为零可 PASS。

实测 7 条：4 条 PASS，3 条 UNKNOWN（口径不匹配无法计算）。

政府补助敏感性：实测 0 条

只有当政府资金确认金额可分离、可追溯，与报告的 profit from operations 在期间、主体、准则、 合并范围、币种上一致，并能证明已计入该营业利润时，才允许计算敏感性。

报告口径下有 15 条政府补助记录，但无一满足「可分离且已计入同口径」，所以敏感性记录为 0。 仅收到未计入损益的现金、资本补助、未摊销递延收益、计入所得税的税收优惠——全部不许调整。 项目的选择是把这个 0 和原因原样写进报告，而不是放宽条件凑一个数出来。

自曝其短已知问题

处置原则：不解决可以，不记录不行。这份清单不构成待办，只构成「已知」。 以下全部已在报告中披露，但都未修复。

A · 已确认的问题

A1 · 事实抽取存在语义错误，且不影响证据状态（最需要关注）

完整追踪见「一个抽错的一生」。 粗筛 4,575 条数值中约 179 条（3.9%）疑似同类问题。 根因：三档证据状态的六条判定全部在判元数据健不健全，没有一条在判抽取语义。

A2 · QUARANTINED 隔离机制从未被真实数据触发

隔离恒为 0，且 RESTRICTED 数量（4,912）与规整阶段 PARTIAL 数量完全相等—— 说明另外两条受限理由从未独立触发过。

两种解读，目前无法区分：采集阶段确实把不合格材料挡在了门外（好事）， 还是隔离机制存在但从未被真实检验（风险）。

A3 · 事实到证据 1:1，证据治理没筛掉任何记录

20,114 → 20,114，一条没少。04 的作用是贴标签不是收窄， 收窄责任全压在 05 挑证据那一步。这符合「保留一切、只限制用途」的设计，但值得记下来。

A4 · 冲突检测被缩到 2 条白名单事实

ADR 0003 的有意取舍，代价是「多来源冲突检测」这个能力在 Demo 里展示不出来。 06 的处置：报告第九章的冲突计数确实全是 0，并附一句说明这是真实承载力， 没有为了让章节好看去造冲突数据。是否扩白名单仍未决。

A5 · gap 优先级轴失去区分度

4,922 条里 4,915 条是 P1（99.9%）。成因是各阶段各自定优先级， 规整阶段的 NORMALIZATION_UNKNOWN（4,912 条机械登记）直接把这一轴淹没。 报告因此显式声明不按优先级筛选，改按 origin_stage × gap_kind 聚合。

为什么不在 06 修：这是 03 的设计缺陷，不是数据 UNKNOWN。 把设计缺陷写成一条运行 gap 是滥用登记册。

均未验证。B2 的结论决定 A1 该修哪一层，验证优先级最高。
