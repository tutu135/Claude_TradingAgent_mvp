# 单股票 Demo 使用冻结研究快照

## Context and Problem Statement

参考产品资料描述了运行时数据抓取和持续更新能力，但本阶段只需用一个中芯国际案例验证取数、规整、治理、分析、质询和报告链路。实时来源会随时间、页面和访问条件变化，也会让同一分析结果难以复现。

需要决定 Demo 是在每次运行时实时取数，还是以固定真实数据切片作为黄金案例输入。该选择会约束所有阶段契约，后续更换成本较高，而且与完整产品的实时方向有意不同，因此记录为 ADR。

## Considered Options

### 运行时实时取数

- 优点：更接近完整产品的长期形态，能展示最新数据。
- 缺点：来源漂移、访问失败和 `as_of` 污染会影响可重复验证；需要连接器、重试、缓存和运行时治理，明显扩大 Demo。

### 冻结、真实、可重复验证的数据快照

- 优点：可以固定输入、规则、哈希和预期流程行为，便于定位规整、溯源与质询问题；不需要生产化取数设施。
- 缺点：不证明实时接入能力；快照更新必须显式产生新版本。

## Decision Outcome

采用冻结、真实、可重复验证的单股票数据快照作为 Demo 黄金案例。`SNAPSHOT_BUILD` 可从符合当前个人非商业使用假设的公开来源准备材料；`DEMO_RUN` 只读取冻结文件，禁止实时刷新或补入 `as_of` 之后的信息。

实时取数保留为后续适配能力，不属于本 Demo 的实现或验收范围。

## Consequences

- 所有权威产物引用同一个 `snapshot_id`，并记录文件与内容哈希。
- 材料变更时创建新快照，不静默覆盖旧快照。
- `smic-4c110e93f810aa8e` 作为 v1 永久保持不变；扩展采集生成新的、自包含的 v2，可记录父快照但不依赖 v1 运行。
- 测试重点是固定输入下的契约、治理、分析和溯源行为，而不是网络可用性。
- 不建设通用连接器、调度、增量同步、缓存服务或实时数据 SLA。
- 本 ADR 不保证快照内容完整；缺失数据仍按 UNKNOWN/TBD 和 gap 规则处理。
