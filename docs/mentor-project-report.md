# 单股票投研 Demo 项目汇报

## 一、项目一句话介绍

这个项目用一份冻结的中芯国际真实公开资料，验证一件事：

> 一份投研报告中的数字和重要判断，能不能沿着证据链追溯回原始材料，并且在重复运行时得到相同结果。

它不是一个可以买卖股票的产品，也不是一个预测股价的模型，而是一个强调“证据可追溯”的工程验证 Demo。

## 二、为什么要做这个项目

普通的自动投研流程容易出现几类问题：

- 数字被模型抄错或混用了不同期间；
- 管理层观点被写成公司已经被事实证明的结论；
- 一段话引用了很多来源，但读者不知道每个数字对应哪一条来源；
- 结论看起来完整，但真正能承重的证据很少；
- 同样的输入重新运行，模型给出不同结果，无法复核。

因此，本项目没有把重点放在“写得像一份研报”，而是放在“每一步是否留下可检查的中间结果”。

## 三、项目固定研究问题

研究对象是中芯国际（`688981.SH`），研究资料截止到：

`2026-05-15 23:59:59 +08:00`

主问题是：

> 截至这个时间点，中芯国际的经常性经营盈利能力发生了哪些可验证的变化？现有证据在多大程度上支持它已经进入可持续改善阶段？

研究允许得出支持、部分支持、反驳或证据不足，不能预先假定结果一定向好。

## 四、整个流程怎么工作

可以把它理解成整理一份复杂档案：

```text
原始材料
  ↓
chunk：按标题、段落、表格切出的原文片段
  ↓
fact：从片段中整理出的单条事实或原文命题
  ↓
evidence：经过来源、口径和可用性治理的证据
  ↓
finding：围绕 D1–D7 七个问题形成的结构化发现
  ↓
challenge：对发现进行反方质询
  ↓
report：生成带证据表和溯源链的内部报告
```

这里最重要的是：材料、chunk、fact、evidence 不是同一个东西。材料被采集进快照，并不代表它已经可信；被检索命中，也不代表它可以支撑结论。

## 五、项目实现的八个业务 Skill

1. `acquire-research-materials`：保存并解析 PDF、HTML、Excel 和文本材料，校验来源、发布时间、`as_of` 和哈希。
2. `govern-research-context`：按结构切分 chunk，运行固定的中英文检索查询。
3. `normalize-research-facts`：把原文整理成带指标、数值、单位、期间和口径的原子事实。
4. `govern-and-validate-research-evidence`：判断来源等级、内容类型、同源关系、冲突和证据状态。
5. `analyze-and-score-research-findings`：为 D1–D7 选择封闭候选集，形成发现并反算证据分。
6. `challenge-research-findings`：从来源、会计可比性、因果归因和证伪缺证四个角度质询发现。
7. `generate-research-report`：生成十章节 Markdown 报告、证据表和数字溯源检查。
8. `single-stock-research-orchestrator`：规定七个阶段的固定顺序，并执行冻结重放和完整性门禁。

仓库中还有测试驱动、代码审查等通用开发 Skill，但它们不属于这八个业务阶段。

## 六、评分是怎么做的

每个维度有两个结果：

- `finding`：`SUPPORTED`、`MIXED`、`NOT_SUPPORTED` 或 `UNKNOWN`；
- `evidence_score`：0 到 3，表示支撑当前判断的证据强度。

证据分不是公司好坏分，也不是投资评级。分数由脚本计算，模型不能自己填写：

- 0：没有可承重的支持证据，必须是 `UNKNOWN`；
- 1：单一来源、单一期间或单点证据；
- 2：有多个独立来源，或有可比较的跨期数值；
- 3：有白名单指标的跨期数值、至少两个独立来源组，并且支持证据中没有未解决冲突。

因此，`MIXED + 3` 是合法的：它表示“混合结论本身有很强证据”，例如年度盈利改善，同时最近季度又出现回落。

## 七、为什么运行时不重新调用模型

首次形成 D1–D7 发现时，每个维度确实需要一次受限模型判断。模型负责理解语义、选择支持和反证，不负责打分。

判断完成后，模型输出被冻结成只读文件。正式 Demo 运行采用 `FROZEN_REPLAY`：

- 重新确定候选集；
- 读取冻结的模型判断；
- 由脚本重新验证、计算证据分并生成报告；
- 运行过程中不再调用模型。

因此，两次干净运行证明的是“从冻结判断输入到最终报告可以确定性重放”，而不是证明模型每次重新判断都会得到相同答案。

## 八、当前实际结果

当前黄金案例包含：

- 20 份冻结材料；
- 3,399 个 context chunk；
- 20,114 条规整事实和证据记录；
- 85 行报告证据表。

质询后的 D1–D7 结果为：

- 5 个维度为 `MIXED`；
- 2 个维度为 `UNKNOWN`；
- 没有维度被判定为 `SUPPORTED`；
- 证据分主要为 2–3。

这不代表项目失败。它说明当前资料可以证明一些变化，但还不能把所有变化归因到单一机制，也不足以证明“可持续改善”已经成立。

## 九、目前最重要的局限

项目已经主动暴露出几个限制：

1. 数值抽取存在语义错误风险：字段可能被抽出来，但指标含义仍可能错。
2. D2、D5、D7 没有可承重的数值指标，部分判断只能依赖文本。
3. 当前真实数据没有触发隔离和未解决冲突机制，机制主要由测试样例证明。
4. 证据治理目前更多是在记录和标注，未必能筛掉所有抽取错误。
5. 这是单股票、离线、内部 Demo，不是多股票生产系统。

这些限制没有被默认值、模型常识或网络补数掩盖，而是以 `UNKNOWN`、gap 和报告警示的方式保留下来。

## 十、项目目前证明了什么

项目目前可以证明：

- 原始材料可以被冻结并保留哈希；
- 研究内容可以拆成可定位的结构片段；
- 事实、证据和发现可以通过 ID 串联起来；
- 证据分可以由脚本确定性反算；
- 报告中的数字可以集中放在带来源的证据表中；
- 冻结输入后的端到端流程可以重复得到相同报告。

项目目前不能证明：

- 所有抽取事实都没有语义错误；
- 模型判断本身一定正确；
- 中芯国际已经进入可持续改善阶段；
- 该方案可以直接扩展成生产级多股票投研平台。

## 十一、希望导师指导的问题

1. 当前“先验证证据链，再考虑扩大范围”的研究路线是否合理？
2. 下一步应优先修复数值抽取语义错误，还是扩大到更多股票案例？
3. 将模型判断冻结后再做端到端复现，是否符合研究可复现性的要求？
4. 对 D2、D5、D7 的证据缺口，应该补充数据，还是保留 `UNKNOWN` 作为研究结果？

## 十二、汇报结论

这个项目的主要成果不是生成了一份看起来完整的研报，而是建立并验证了一条较严格的证据链：

> 原始材料是什么、抽取了什么、哪些内容被治理为证据、哪些证据支撑了哪个发现，以及哪些地方仍然不能确定，都可以被追查和复核。

它目前更像一个“投研证据工程的可行性验证”，而不是一个已经完成的自动投资研究产品。
