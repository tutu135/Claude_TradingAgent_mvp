# 单股票投研 Demo 范围

## 目的

本 Demo 用一个可重复的真实单股票案例验证“取数到报告”的投研业务链路、规则边界和数据契约。它是个人、非商业、本地使用的业务验证载体，不是未来前后端产品的架构原型。

需求优先级如下：本次访谈确认的范围与决策高于现有参考资料；参考资料只用于补充事实和发现矛盾，不能覆盖本文件的明确边界。

## 固定案例

- 股票：中芯国际。
- 证券：`688981.SH`。
- 研究市场：上海证券交易所科创板 A 股。
- 港股披露只能作为发行人层面的候选材料，不构成第二研究标的，也不得混入 A 股行情或估值口径。
- 案例来源：`case_origin=model_generated`。这表示案例流程在本次新建，不表示数据由模型生成。
- `as_of`：`2026-05-15T23:59:59+08:00`（Asia/Shanghai）。
- `as_of` 是信息最晚公开时间，不是财务报告期末。发布时间晚于该时点的材料不得进入本版本快照。
- Snapshot v1：`smic-4c110e93f810aa8e`，保持不可变，仅代表 Ticket 01 当时冻结的 7 份材料。
- Snapshot v2：`smic-95dcd12eba2fe17c`，Ticket 02 形成的自包含历史结果。
- 当前 Snapshot v3：`smic-a283e95e2c9e8068`，以 v2 为父快照并冻结 20 份 `ACQUIRED_UNASSESSED` 材料；Ticket 03 只读取 v3，运行时不依赖 v1/v2。

主研究问题：

> 截至 `{as_of}`，中芯国际的经常性经营盈利能力发生了哪些可验证的变化，现有证据在多大程度上支持其已进入可持续改善阶段？

## 范围内能力

Demo 只实现以下顺序：

1. 取数与材料解析；
2. 上下文治理；
3. 技术标准化和会计规整；
4. 信源分级、内容分类、冲突处理和溯源；
5. 确定性治理核验；
6. 分析推理和固定框架评分；
7. 反方质询；
8. 内部报告生成。

## 八个 Skills

交付一个编排 Skill 和七个阶段 Skill：

1. `single-stock-research-orchestrator`
2. `acquire-research-materials`
3. `govern-research-context`
4. `normalize-research-facts`
5. `govern-and-validate-research-evidence`
6. `analyze-and-score-research-findings`
7. `challenge-research-findings`
8. `generate-research-report`

编排器只执行固定顺序、状态记录、停止条件和最多两轮质询，不建设通用工作流引擎。阶段 Skill 不直接互调；修订由编排器显式返回目标阶段。

## 取数模式

`acquire-research-materials` 定义两种用途，但不建设通用连接器框架：

- `SNAPSHOT_BUILD`：使用当时可用且符合个人非商业使用假设的公开工具、Web 检索或人工准备材料，生成冻结研究快照。
- `DEMO_RUN`：只读取冻结研究快照，禁止实时刷新、临时网络补数和使用 `as_of` 之后的材料。

采集准入和证据准入严格分离。材料只要发布时间不晚于 `as_of`、采集来源/展示发布主体/材料定位可记录，并且取得内容可以冻结和通过哈希复核，就以 `ACQUIRED_UNASSESSED` 进入新快照。采集阶段不判断真实性、完整性、可信度、T1–T4、内容类型、同源、冲突、隔离或证据资格。

采集来源、展示发布主体、发布时间/窗口或材料定位暂缺的高相关线索放入 Snapshot 之外的候选材料暂存区，不进入 RAG、事实提取、分析或报告。补齐采集证据并经用户确认后才能进入后续快照。已确认发布时间晚于 `as_of` 是材料内容在业务层面的唯一直接排除条件。

支持解析带可靠文本层的 PDF，包括正文、表格、页码、章节和脚注定位，并可渲染页面进行抽取结果和版式核对。正式溯源必须指向原始 PDF；`tmp/pdfs` 只能存放辅助抽取或视觉核对产物。扫描件/纯图片 PDF OCR，以及从图片或图表中识别数值，不属于 Demo 范围。

商业数据源当前不可用。不得实现或虚构 Wind、iFinD、Choice、Bloomberg、付费研报库或未知 API 的适配器、字段和调用样例。

## 来源使用假设

Demo 假定为个人、非商业、本地使用，不公开、不共享给客户、不销售，也不用于模型训练。

- 可取得材料包括无需登录即可取得的材料，以及由用户通过自己的账号、权限或合法渠道手动取得并提供给项目的材料。
- 账号注册、登录、验证码和会话由用户在 Demo 外手动处理；项目不得保存账号、密码、Cookie、Token 或其他会话信息，也不自动登录或绕过访问控制。
- 条款入口、已知限制和 `usage_basis` 尽力记录；缺失或尚未判断不阻止采集，也不建设许可审批流。
- 不再要求采集前填写 `restriction_status=USABLE`；后续治理决定限制、隔离和证据用途。
- 第三方原始资料不进入可分发产物；内部快照可以保存取得的原文件，报告只保留必要短摘录、来源定位和哈希。
- 若用途变为团队共享、公开展示、客户交付或商业产品，来源许可重新成为 P0。

## 采集目标与停止条件

核心观察期为 2023 财年至 2026 Q1。更早材料仅在解释期初基线、交易链、子公司和合并范围、会计政策/重述或必要行业周期背景时纳入。

当前 v3 沿用并完成以下固定采集目标的搜索与冻结：

- 公司与证券主数据；
- 2023、2024、2025 三个年度的完整年报材料组；每年包括完整合并 IFRS 年报，以及可取得且单独发布的 A 股 CAS 年报或财务披露；
- 2025 Q2、Q3、Q4 和 2026 Q1 的季度材料组，包括业绩公告、财务附表、演示文稿、已有文字交流记录及直接相关交易所公告；
- 产能、利用率、出货、ASP、制程结构、应用结构和资本开支；
- 政府补助、其他经营收入及 IFRS/CAS 调节；
- 晶圆代工、成熟制程和需求周期；
- 中芯北方 49% 股权交易、NSI 交易、子公司及合并范围变化、会计政策和重述事件；
- D1–D7 所需的其他直接相关材料。

每份材料至少映射一个采集目标。目标映射只解释为什么采集，不能使用 `COVERED/PARTIAL` 宣称数据完整或证据充分。行情、估值、目标价、同行比较和一般新闻只有在直接解释上述目标时才采集，仍不进入固定评分。

采集按发行人、监管、官方行业/政府、具名机构和扩展 Web 渠道搜索。所有目标完成适用渠道搜索，并针对剩余缺口的一轮补充搜索没有发现新的目标相关材料后，视为搜索饱和，可以冻结新版本快照。v3 已达到该停止条件；搜索饱和不表示数据完整，未找到的具体材料和不可提取材料仍记录为采集缺口，不得提前写成事实 UNKNOWN。

## 轻量 RAG

上下文治理可以使用单案例、本地、可重建的轻量 RAG：

- 只索引冻结快照中可提取且与研究目标相关的待治理材料；
- 保留材料、页码、章节、表格和文本哈希；
- 必须提供关键词或 BM25 基线；
- Embedding 或混合检索只在 BM25 为 WARN 且预登记具体词法漏召回时允许一次同集实验；只有 WARN 转 PASS 且硬指标不退化的方案可被采用；
- 检索结果只是候选上下文，不能直接成为事实或证据；
- 在治理验证中记录命中、定位和漏召回案例；
- 不建设向量数据库服务、增量同步、长期知识库、重排服务或检索 API。

## 交付形态

- 八个 Skills；
- 集中管理的配套脚本；
- 单一来源的固定业务规则；
- 固定文件数据契约；
- 一个可追溯的中芯国际黄金案例；
- 一份 Markdown 内部报告及 YAML/JSONL 支撑文件。

配置和汇总使用 YAML，逐条记录使用 JSONL，报告使用 Markdown。`data-snapshot.csv` 如需兼容参考资料，只能从权威 JSONL 派生，不能成为第二事实源。

## 报告边界

报告是“每个数字带来源与时点、经过反方质询的可追溯结构化分析报告”。它可以输出证据约束的研究发现，但不替用户形成投资决策。

- 固定 `distribution_status=INTERNAL_DEMO_ONLY`。
- 始终可以生成内部诊断报告，不设最低证据分。
- 独立记录 `governance_status=PASS/WARN/FAIL`。
- 治理失败时，受影响数据必须隔离，不能支撑研究发现。
- 只生成 Markdown，不生成 PDF、网页、Dashboard、API 或正式发布物。
- 不输出买入、卖出、持有、仓位、目标价、估值锚、投资吸引力判断或系统自己的盈利预测。
- 管理层指引和第三方预测只能作为已分类的来源观点呈现。

## 明确不做

- 瞭望塔；
- 赛道或行业研究交付物；
- 两标的对比；
- 多股票、股票池、组合或持仓；
- 模型路由；
- 记忆和自进化；
- 假设台账及后续自动跟踪；
- 多模态、音频转写、图片/图表数值理解和扫描件/纯图片 PDF OCR；
- 动态研报或运行时刷新；
- 估值、目标价和交易建议；
- 通用数据连接器、规则引擎、插件系统和工作流平台；
- 数据库、队列、长期服务、发布系统、前端或后端；
- 为未来产品预建的抽象层。

## 简洁性约束

- 本项目是有明确边界、可随时调整或废弃的单股票 Demo。当前目标是用冻结的中芯国际黄金案例跑通并验证研究方法和完整业务链路，不是建设面向未来场景的健壮平台。
- 只实现运行黄金案例和满足已确认验收标准所必需的能力。
- 优先使用固定、案例专用、透明且容易修改的文件契约、规则和脚本。
- 不得仅以“增强鲁棒性”“未来可能复用”“以后可能扩展”为理由增加抽象层、框架、服务、状态模型或依赖。
- 如果一个已知问题不影响黄金案例跑通、关键结果正确、ID 链可追溯和固定验收通过，应将其记录为明确限制或 gap，而不是为其建设通用解决方案。
- 多个方案都满足当前要求时，选择组件、依赖、状态和调用链更少，并且更容易删除、替换或重写的方案。
- “容易调整”通过短小直接的代码、显式规则和固定数据文件实现，不通过插件系统、通用 DSL、扩展框架或预留架构实现。
- 只为当前 Snapshot v3 和黄金案例中实际出现的问题编写处理逻辑；不为假设中的其他公司、格式、用户或运行环境预建兼容能力。
- Demo 的完成标准是黄金案例能够确定性、可复现地跑通并证明方法可行，不是达到生产系统的通用性、容错性、性能或长期维护水平。
- 简洁性不得用于放宽冻结 Spec 的硬约束，包括禁止虚构数据、关键定位准确、公式可复算、核心漏召回门槛和原始材料可追溯。
- Skills 编排可以在未来产品中被完全弃用。
- 每个新增组件必须能指向本 Spec 的一个当前验收条件。
- 固定文件和简单脚本能够满足要求时，不引入服务或框架。
- 业务规则只保存一份，Skills 通过引用使用，不复制规则正文。
- 配套脚本集中管理，不随每个 Skill 重复分发，不建设 SDK。
- 所有 UNKNOWN/TBD 汇总到一个案例缺口文件和一个需求开放问题文档，不建设状态服务。
